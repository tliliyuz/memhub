# DOCUMENT GOVERNANCE — 文档治理指南

| 适用范围 | 文档归属、事实状态、冲突裁决与文档变更门禁 |
| 不负责 | Markdown 排版模板与 ADR 触发条件；它们分别见 DOCUMENT_FORMAT 与决策索引 |

本文件定义如何发现、归属、裁决、固化与验证产品与工程事实：一个事实应进入哪份
文档、实现与规范冲突时怎么办。标题、编号、模板与冗余边界由
[DOCUMENT_FORMAT](DOCUMENT_FORMAT.md) 定义，架构取舍是否需要 ADR 由
[决策索引](../decisions/README.md) 定义。

任何 Markdown 的新增、修改、删除或移动开始前，必须先完整阅读本指南与
DOCUMENT_FORMAT。该动作与 ADR 检查一样是强制前置门禁，不能以「只改一句」、
「只补链接」或「纯文档」为由跳过。

## 1. 治理目标

- 规范是实现输入，不是对既有代码的追认记录。
- 同一事实只有一个权威来源，其他文档只引用或记录状态。
- 明确区分当前实现、已批准目标、迁移过程与验证结果。
- 测试只能执行规范，不得凭自身存在为未授权行为取得合法性。
- 任何例外都有负责人、理由、期限与退出条件，不形成无期限兼容债务。

## 2. 文档类型与职责

| 类型 | 回答的问题 | 不得承担 |
|---|---|---|
| 需求规范 | 做什么、为谁做、如何验收 | 技术实现步骤 |
| 架构规范 | 服务边界、数据分层、部署拓扑与演进门禁 | 重要取舍的讨论历史 |
| 接口契约 | 端点、请求字段、响应与空态语义 | 页面交互、表结构 |
| 环境变量 | 键名、读取方与失败语义 | 部署步骤 |
| 数据口径 | 字段、覆盖边界与质量缺口 | 产品行为定义 |
| 运行周期 | 周期、幂等键、业务日切分与结算 | 建表 DDL |
| ADR | 为什么选择一项长期方案 | 当前施工清单 |
| 计划 | 何时、按什么依赖顺序交付 | 宣称能力已经实现 |
| 指南 | 如何执行开发与治理动作 | 定义产品行为 |
| 变更记录 | 已发生的可审查变化与验证结果 | 未来计划、未运行结果 |

完整的主题归属以入口文件的权威文档矩阵为准；本表只约束「类型承担什么」，不
枚举每个仓的全部文件。

## 3. 事实状态模型

每项需要跨文档跟踪的行为只能处于以下状态之一：

| 状态 | 判定条件 | 可以声称 |
|---|---|---|
| `observed` | 已从代码、运行结果或旧文档取证，尚未裁决 | 「当前观察到」 |
| `proposed` | 已提出可审查方案，尚未获负责人确认 | 「建议」 |
| `specified` | 权威规范已获确认，可导出明确验收条件 | 「已批准规范」 |
| `implemented` | 实现已完成，但尚未完成要求的完整验证 | 「已实现，待验证」 |
| `verified` | 规范要求的测试与门禁均有本次实际证据 | 「已验证」 |
| `deprecated` | 已提供替代方案、观测窗口与退出条件 | 「已弃用，兼容中」 |
| `retired` | 消费方已退出，兼容入口或旧格式已移除 | 「已移除」 |

不得把「文档状态为已确认设计」解释为功能已经实现；不得把旧测试通过解释为其
断言行为已获规范授权。

## 4. 文档变更门禁

任何文档变更先执行格式与治理预检；涉及行为时再继续事实与 ADR 门禁：

```text
完整阅读 DOCUMENT_FORMAT 与 DOCUMENT_GOVERNANCE
  → 识别文档类型和唯一权威来源
  → 事实取证
  → 确定唯一权威来源
  → 冲突分类
  → ADR 检查与裁决
  → 更新权威规范
  → 导出验收条件与测试
  → RED / GREEN / REFACTOR
  → 更新变更记录与状态
  → 格式、引用、链接与职责检查
```

门禁规则：

1. 未读完两份指南，不得编辑任何 Markdown。
2. 取证前不提出修复方案；至少检查权威规范、当前实现、相关测试与近期提交。
3. 权威来源缺失或两份权威文档定义同一事实时，暂停测试与实现。
4. ADR 检查必须先于规格裁决；命中项按决策索引解除门禁。
5. 实现与已确认规范冲突时默认修正实现；修改规范需要独立理由与负责人明确批准。
6. 负责人未明确选择「实现服从规范」或「规范变更」前，不得用测试固化任一方案。
7. 完成声明必须分别说明规范、实现与验证状态，不能用一个「完成」覆盖三者。

## 5. 冲突分类与处理

- 实现偏离规范：规范已唯一明确，按缺陷处理，规范不变，从规范导出正确验收测试。
- 实现领先、规范缺失：标记 `observed` 并暂停扩展；由负责人裁决删除收敛或正式采纳。
- 迁移态与目标态不同：完整记录当前态、目标态、迁移步骤、消费方、观测、退出门禁
  与删除时点；同一迁移事实只在一个位置定义，其他文档链接引用。
- 权威文档冲突：按入口文件的权威矩阵确定唯一归属；归属文档保留定义，其他文档
  删除重复描述并改为链接。矩阵不能裁决时先由负责人确认归属。

不得选择更方便当前实现的一方，也不得仅因代码已存在或测试已通过就选择正式采纳。

## 6. 文档裁决候选

每个待裁决问题使用以下格式，一次只处理一个逻辑事实：

```text
文档裁决候选
- 候选标题：
- 发现日期：YYYY-MM-DD
- 当前实现事实：
- 当前测试事实：
- 唯一权威来源：
- 冲突类型：实现偏离 / 实现领先 / 迁移态 / 文档冲突
- 当前态：
- 已批准目标态：
- 可行方案：至少两个
- ADR 检查结果：
- 建议裁决：
- 受影响文档、测试与实现：
- 迁移和退出条件：不适用时写「不适用」
- 负责人裁决：待确认
```

有效裁决必须明确回复一种：`实现服从规范：<理由>`、`批准规范变更：<方案与理由>`，
或 ADR 治理要求的 `创建 ADR` / `豁免 ADR：<理由>` / `未命中 ADR：<理由>`。
「继续」「可以」等普通实施授权不能替代存在冲突时的文档裁决。

## 7. 冗余与篇幅控制

- 一个章节只解决一个问题；一个段落只表达一个主题，超过五句即拆分。
- 非权威投影最多保留一个摘要段或三个摘要条目，随后链接权威来源。
- 历史过程只进入 ADR 或变更记录；当前规范不保留逐次讨论与临时状态。
- 完整清单、矩阵、Schema 或状态机只维护一份；发现第二份必须当次收敛。
- 入口文件只保留硬约束与索引；长篇论述放入 `docs/` 下的权威文档。入口总行数与
  本仓专属块行数由 `entry_budget` 检查约束。

## 8. 评审检查表

- [ ] 同一事实只有一个权威来源；
- [ ] 修改前已完整阅读 DOCUMENT_FORMAT 与 DOCUMENT_GOVERNANCE；
- [ ] 文档类型、章节模板、标题编号与条目语法符合 DOCUMENT_FORMAT；
- [ ] `AGENTS.md` 与 `CLAUDE.md` 逐字节一致，入口未超出预算；
- [ ] ADR 检查结果满足治理规则；
- [ ] 当前态、目标态与实现状态没有混写；
- [ ] 迁移例外包含消费方、观测与退出条件；
- [ ] 验收条件可以直接转化为自动化测试；
- [ ] 变更记录只记录实际发生的变化并包含日期；
- [ ] 没有 `TBD`、`TODO`、无期限「临时」或无法验证的描述；
- [ ] 链接、标题、Schema 引用与版本号可解析，且没有绝对路径；
- [ ] 没有密钥、口令或 token 值；
- [ ] 实现与测试没有被当作规范来源；
- [ ] `governance verify` 与 `git diff --check` 均通过。

任一项不满足时，文档评审不得通过，后续测试或生产实现保持暂停。

## 9. 增量防漂移

1. 在唯一权威来源修改事实，并保留稳定章节链接。
2. 运行 `governance verify`；按失败清单修本仓内容，而不是改受管通用规范。
3. 修改权威文档后，检索仓库内对它的引用，只更新真正受影响的投影与状态。
4. 标记为 `deprecated` 的文档只保留弃用原因、迁移入口与历史说明，不得新增契约事实。
5. 行为事实变化时继续执行 ADR / 规格 / 测试门禁；纯归属或导航变化不扩展为业务实现。
