# DOCUMENT FORMAT — 文档格式规范

| 适用范围 | 仓库内 Markdown 文档的结构、编号、表达与冗余边界 |
| 不负责 | 事实归属、冲突裁决与 ADR 触发条件；见 DOCUMENT_GOVERNANCE 与决策索引 |

本文件只定义文档的结构、编号、表达与冗余边界。事实归属与维护流程由
[DOCUMENT_GOVERNANCE](DOCUMENT_GOVERNANCE.md) 定义，架构取舍由
[决策索引](../decisions/README.md) 定义。

## 1. 通用格式

### 1.1 标题与元数据

- 每个文件只允许一个 H1，格式为 `# 英文标识 — 中文标题`；ADR 使用
  `# ADR-NNNN — 标题`，README、CHANGELOG、入口文件可按各自模板例外。
- 权威规范、技术文档、数据文档、计划与指南在 H1 后放元数据表，字段按「文档状态、
  最后更新、适用范围、不负责、相关决策」排序；无值字段写「无」而不是省略该行。
- 权威规范、技术文档与数据文档必须填写「适用范围」与「不负责」。
- 规范与计划状态只使用 `observed / proposed / specified / implemented / verified /
  deprecated / retired`；ADR 使用 `proposed / accepted / deprecated / superseded`。

### 1.2 标题层级与编号

- 权威规范、技术文档、数据文档与指南的 H2 使用连续整数：`## 1. ...`、`## 2. ...`，
  不得跳号。
- H3 在同一 H2 下存在两个及以上并列主题时使用 `### 2.1 ...`；只有一个子主题时
  直接写入 H2。
- H4 只用于 H3 内确有两个及以上并列子主题的长章节；不得用加粗段首模拟标题。
- 标题编号表达文档结构，不表达版本、优先级或实施顺序。
- ADR 使用固定语义标题，不手工编号章节；选项使用 `### 方案 A`、`### 方案 B`。

### 1.3 段落、列表与表格

- 一个段落只表达一个主题，建议不超过五句；超过时拆成小节、列表或表格。
- 并列要求使用无序列表，严格先后顺序使用有序列表，状态映射或字段对照使用表格。
- 同一列表的条目使用一致语法与标点；完整句以中文分号结尾、末项以句号结尾，
  短语列表不加句末标点。
- 表格每行只表达一个可独立审查的事实；单元格不得塞入多阶段实施流水账。
- 表格单元格内的竖线必须转义，否则整张表会被解析错位。
- 命令、Schema、状态机与流程图使用代码块；不得用代码块承载普通说明文字。

### 1.4 链接与引用

- 首次引用本仓文档时使用相对链接；后续可用稳定文档名或章节号。
- 同一仓库内引用一律使用相对路径，不得写入绝对路径，否则换机即失效。
- 跨文档只引用权威事实，不复制整段定义；引用必须说明关联点。
- 章节改号时必须同步仓库内全部引用；文件移动时必须同步目录索引与反向链接。
- 不使用裸路径代替可点击链接，代码块或命令中的路径除外。

## 2. 内容组织与冗余

### 2.1 单一职责

| 文档类型 | 只回答 | 不得承载 |
|---|---|---|
| ADR | 为什么选择该长期方案 | 当前施工清单、重复规格 |
| 规范与技术文档 | 当前有效目标、边界、失败语义、验收门禁 | 讨论过程、逐次提交记录 |
| 计划与路线图 | 目标、范围、依赖、退出门禁 | 测试用例、逐批操作步骤 |
| 测试用例 | 前置、操作、预期 | 排期、实现方案、完成声明 |
| 变更记录 | 已发生的变化与实际验证 | 未来计划、未执行结果 |
| README | 导航、入口、最短使用说明 | 专项规范正文 |
| 入口文件 | 硬约束与权威文档矩阵 | 长篇通用论述 |

### 2.2 投影长度

- 非权威文档对同一事实最多保留一个摘要段或三个摘要条目，并链接权威来源。
- 实施批次、验收矩阵、字段定义与状态机只能各有一个完整版本。
- 历史背景只保留在 ADR 与变更记录；规范正文只保留影响当前行为的结论。
- 同一文档出现第二份相同清单时，保留职责最匹配的一份，其余改为链接。

### 2.3 当前态与目标态

- `observed`、`proposed`、`specified` 与已实现状态必须分段或分表展示。
- proposed 内容必须在标题或元数据中标识，不能混入 accepted 条目而不标状态。
- 完成状态只在计划汇总与变更记录取证；规范只声明当前有效行为与尚未实现的已批准目标。

## 3. 文档类型模板

### 3.1 权威规范、技术文档、数据文档与指南

```text
# NAME — 中文标题

元数据表

职责声明 / 导航

## 1. 目标与范围
## 2. 核心定义或结构
## 3. 行为、边界或执行规则
## 4. 失败与安全语义
## 5. 验收或验证
## 6. 当前状态与门禁
## 7. 变更治理
```

可按主题增加或合并章节，但同一文档内的编号必须连续，章节顺序保持「定义 → 行为 →
约束 → 验收 → 状态」。

### 3.2 ADR

```text
# ADR-NNNN — 标题

元数据表：状态、日期、决策人、相关决策

## 背景
## 决策问题
## 备选方案
## 决策
## 边界
## 后果
## 验收条件
## 修订记录
```

- accepted ADR 不保留「候选」「建议采用」等未决措辞；历史候选内容归入备选方案。
- 修订写入同一修订记录，当前有效决策只在决策与边界各定义一次。
- 被替代 ADR 保留历史内容并标记 `superseded`，不得重写为当前规范。

### 3.3 README 与目录索引

- 根 README：项目定位、最短启动路径、文档入口。
- 目录 README：本目录职责、文件索引、阅读顺序。
- README 不复制规范、ADR 或完整环境指南。

### 3.4 变更记录

- 新条目放在文件顶部，使用 `- **主题（YYYY-MM-DD，类型/状态）**：摘要`。
- 每条只记录一个逻辑变化，可包含范围、验证与状态三个短段，不写后续待办清单。
- 实际命令与结果必须与本次执行一致；未运行内容不得写成通过。

## 4. 格式验收

- [ ] H1 唯一，标题层级不跳级；
- [ ] 需要编号的 H2/H3 连续且与父级一致；
- [ ] 没有用加粗段首代替标题；
- [ ] 当前态、目标态与历史没有混写；
- [ ] 同一事实、清单或表格只有一个完整来源；
- [ ] 新增或改号章节的链接已同步；
- [ ] 权威文档边界元数据完整，弃用文档没有新增契约事实；
- [ ] 无绝对路径链接、无密钥与口令；
- [ ] `governance verify` 与 `git diff --check` 通过。
