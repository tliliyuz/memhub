# ADR-0001 记忆能力不进入模型请求路径

| 属性 | 值 |
|:---|:---|
| 状态 | accepted |
| 日期 | 2026-11-18 |

## 背景

旧 memhub 用 Memory Proxy 站在模型请求路径上，同时承担转发与记忆。由此产生的故障：

- upstream 段 ~10.4s `fetch failed` 导致 502；
- 配置挂载失败后回退 DEFAULT_CONFIG（占位 upstream），进程仍判定健康；
- `MEMORY_USER_KEY` 缺失时能力静默降级；
- Proxy 日志写满磁盘，最终导致全栈清空。

共同点：**记忆的正确性与模型的可用性绑死在同一跳上**，任一方故障放大为双方故障。

## 决策

1. 模型调用直连上游，memhub 不出现在任何模型请求路径中。
2. 采集在客户端以独立进程（collector）完成，只做字节搬运，主动推送；云端不反向连本地。
3. 记忆链路的任何故障，只影响知识新鲜度，不影响用户当前工作。

## 备选与否决理由

| 备选 | 否决理由 |
|:---|:---|
| 修好 Proxy（超时、健康检查、配置校验） | 仍是同一拓扑，故障域未变；且历史上每修一处暴露下一处 |
| 客户端本地 relay 转发 + 旁路采集 | 仍需维护长连接与本地状态，换机即失效 |
| SSH 隧道常连云端 | 网络抖动即断；仅保留为开发期手段 |

## 后果

- collector 必须无状态、可随时停机；状态只放云端游标与本地 state 文件。
- 云端承担全部 LLM 调用与凭据，worker 可独立扩容/重启。
- MCP 走远端 `/mcp`，不再依赖本地进程。
- 代价：采集有延迟（分钟级），且需要设备注册与 token 吊销机制。
