# ADR-0019 MCP 只读长期记忆工具（修订 ADR-0016 决策 7）

| 属性 | 值 |
|:---|:---|
| 状态 | proposed |
| 日期 | 2026-11-26 |

## 背景

[ADR-0016](ADR-0016-long-term-memory.md) 把长期记忆做成独立于各知识库的部署级记忆层，第一期只注入会话抽取，决策 7 明确「MCP 第一期不暴露记忆（后续如需由独立只读工具承载）」，实施规格 §12 也把「记忆正文是否需要单独的只读 MCP 工具」列为待评审。第一期已合入 `dev`：记忆按周发布快照，内容为跨项目 canonical 节点聚合出的准则，带结论、适用边界、失效条件、置信度与证据。

现在需要让 MCP 消费方（Claude Code 等 agent）能读到这层准则，减少「每个项目重新踩坑」。难点不在工具本身，而在**可见性边界**：记忆是部署级全局层，现有 MCP 凭据的边界是「库名单 + `mcp:read`/`mcp:write` 作用域」；一条记忆通常由多个项目的证据合成，无法归属到单一库。若直接按现有读凭据开放，一个只授权了 A 项目的 agent 会读到由 B、C 项目会话提炼出的结论，越过现有库范围授权。

本 ADR 按触发清单第 3 项（改变 MCP 工具契约）与第 7 项（改变访问控制边界）创建；未 `accepted` 前不写规格、测试与实现。

## 决策

1. **只读、两个工具**：新增 `kb_memory_search` 与 `kb_memory_read`。不提供记忆写入、更新、废弃、候选查询、快照发布/回滚/停用等治理动作；记忆写入仍只由聚合任务（系统 actor）与管理台负责人完成（ADR-0016 决策 3）。工具名保留 `kb_` 前缀，与现有工具的发现口径一致。
2. **数据面只读「已发布快照」**：两个工具都只读当前 `published` 快照的 `entries`，与 worker 注入使用同一冻结口径；没有已发布快照时 `kb_memory_search` 返回空结果与 `hint`，`kb_memory_read` 返回 `3001`。不暴露未发布变更、聚合候选与修订历史，也不允许 MCP 触发发布。
3. **可见性需要凭据显式开启**：`Grant` 增加可选布尔 `memory`（默认 `false`），与 `projects` 正交——库名单回答「能读哪些项目的知识」，`memory` 回答「能读部署级记忆层」。令牌生成器 `memhub mcp token` 增加 `--memory`；stdio 本机全库权限同时包含记忆工具。未开启的凭据 `tools/list` 仍只看到原有工具，调用记忆工具返回 `3001`，与越权直读同码，不泄露快照是否存在。
4. **返回内容限于准则与证据元数据**：
   - `kb_memory_search`：`query`（1–512 字符）、`limit?`（默认 5，1–20），对 `title + conclusion + boundary` 做应用层 BM25，沿用 worker 的选择逻辑；结果项含 `slug`、`title`、`conclusion`、`boundary`、`confidence`、`score`，顶层带 `version`（快照版本）。无命中返回空列表与 `hint`。
   - `kb_memory_read`：`slug`，返回 `title`、`conclusion`、`boundary`、`invalidation`、`confidence`、`status`、`revision`、`evidence`（`project` / `session` / `session_ref` / `observed_at`）、顶层 `version`。不返回记忆修订历史、候选、内部映射或聚合输入节点正文。
   - 两个工具都只返回快照里的 `active` 条目；已废弃条目、被替代关系不暴露。
5. **审计与轨迹**：读调用只进 `kb_mcp_trace`（工具名、状态、耗时、参数摘要等既有字段，不记录查询词与记忆正文），不写 `kb_write_audit`；返回的 `version` 让调用方能把结论与快照版本对照。
6. **自描述**：工具描述明确「跨项目长期准则，只作判断与归一化参考，不是事实证据，不能按原文引用」，并写清需要显式开启才可见。
7. **契约版本**：`mcp-tools.md` 升 0.9，新增工具行、`Grant.memory`、错误码复用与 `tools/list` 裁剪矩阵；`contracts/README.md` 升 0.18。

## 备选与否决理由

- **任何有效读凭据都可读记忆**：实现最省事，但一个只授权 A 项目的 agent 会读到 B、C 项目的合成结论，等于用「读知识」的授权读到了跨库派生内容；与现有「库名单即边界」的承诺冲突，否决。
- **按证据项目与授权库求交集过滤**：一条记忆的证据常跨多个库，过滤后要么只剩部分证据、要么整条不可见，语义变成「按证据片段拼接的伪记忆」；且交集随聚合轮次漂移，调用方无法预期，否决。
- **新增 `mcp:memory` 作用域**：作用域当前是「读/写」的粗粒度身份，把数据面授权塞进作用域会让 `mcp:read + memory` 这类组合无法表达，也影响 `mcp:write` 的隐含读语义；改用 grant 上的正交布尔，否决新作用域。
- **复用 `kb_search` 或把记忆混入 `kb_nodes`**：ADR-0016 已裁决记忆不进入节点检索、不新增 `Kind`；混入会让 tier、库范围与节点 schema 都失去区分度，否决。
- **提供 MCP 记忆写工具**：与 ADR-0016 决策 3「agent 不能把自身输出升格为准则」直接冲突，否决。
- **MCP 读取未发布或候选记忆**：会让半成品绕过发布与冻结影响外部 agent，回滚只能事后补；否决。

## 后果

- 凭据契约新增 `memory` 布尔，`memhub mcp token` 新增 `--memory`；既有凭据默认看不到记忆，需重新签发或显式加开关。`tools/list` 数量从 4/7 变为 4/7 或 6/9（按 `memory` 开启与否），客户端需按发现结果而非硬编码数量处理。
- 记忆成为跨项目 agent 的显式可读层后，一条错误准则会同时影响所有开启该能力的 agent；仍靠证据门槛、周快照、人工废弃与停用控制，且 MCP 无写入口。
- 读取不产生额外 LLM 成本；查询只读快照 JSONB 与 SQL 过滤，成本可忽略。
- 实施前仍需在规格阶段定：字段长度与分页上限、BM25 参数与阈值（是否与 worker 注入一致）、无快照与空查询的提示文案、证据字段的裁剪深度、错误码的具体映射、stdio 与 HTTP 的 `tools/list` 快照。
