# ADR-0016 长期记忆独立成域，并反向注入会话抽取

| 属性 | 值 |
|:---|:---|
| 状态 | accepted |
| 日期 | 2026-11-26 |

## 背景

当前知识真源是 PG `kb_*` 表（ADR-0013），每条知识挂在某个 `kb_project` 下，id 为 `<project>/<kind>/<slug>`。这个模型适合项目事实、决策、坑与操作步骤，但有两处覆盖不到：

- **跨项目不连通**：同一类问题在 A 项目总结出的方法，进入 B 项目后既不可见也不复用。方法论目前只能由负责人人工总结，且下个项目无法自动继承。
- **单会话抽不出趋势**：worker 的抽取粒度是单文档/单会话，且只允许 fact / decision / procedure / pitfall（`worker/extract.py` 的 `SESSION_KINDS`）。跨会话、跨项目的准则需要在更长窗口上聚合；单会话抽取勉强产出只会得到「伪方法论」。

两条先前的候选路径都不成立：

- 把 `methodology` 作为新 `kind` 放进项目库：每项目各存一份，内容重复且漂移，无法跨项目串联。
- 用一个 `global` 知识库承载：记忆被迫套用知识库与采集目标语义（`kb_projects` 外键、采集目标校验、库范围授权），容易被误当作采集目标，也无法表达「记忆版本反馈到抽取提示」的生命周期。

目标是把「从大量会话与长期开发过程中提炼的准则」做成独立于各知识库的长期记忆层，并能反向影响抽取，让抽取随积累改进。

## 决策

1. **独立记忆域**：新增记忆表（表名待规格阶段定，候选 `kb_memory_entries` / `kb_memory_revisions` / `kb_memory_snapshots`），不挂在 `kb_projects` 下，不使用 `<project>/<kind>/<slug>` id 规则，**不新增 `Kind` 枚举值**，不参与项目库检索结果。
2. **条目形态**：一条记忆是有版本、有证据、可废弃的准则，至少包含：一句话结论、适用边界、失效条件或反例、证据引用（跨项目节点 id、会话片段引用、涉及的 library 与时间跨度）、置信度、状态（`active` / `deprecated`）、修订号、`superseded_by`。正文不记录时间线过程。
3. **写入者边界**：只有周期聚合任务（系统 actor）与管理台负责人可写记忆；采集端、MCP 写工具、会话抽取 worker 都不能写，避免 agent 把自身输出直接升格为准则。
4. **提炼**：新增周期聚合任务（默认每周），证据**以跨项目 canonical 节点为主**，必要时回 `raw_store` 原始会话核对引用。默认门槛为「≥3 个独立会话且 ≥2 个项目」才允许成条，未达门槛只保留证据关联，不生成记忆。冲突走 `contradicts` 治理裁决，不自动合并。
5. **发布与冻结**：记忆按**版本化快照**发布，默认按周发布。会话抽取固定使用当前已发布的快照，不在任务运行中热切换；每次抽取在审计中记录所用的记忆版本，保证可复现与可回滚。坏版本可整体停用。
6. **注入范围（第一期）**：只把 `active` 记忆注入**会话抽取提示词**，作为判断与归一化准则，按相关性取 top-k（默认 5–10 条）并设 token 预算。聚合任务自身不读记忆，避免「记忆指导记忆」的自证循环。
7. **可见性**：记忆不进入 `kb_nodes` 检索；MCP 第一期不暴露记忆（后续如需由独立只读工具承载）；管理台提供独立的「长期记忆」入口。记忆**不能作为采集目标**。

## 备选与否决理由

- **新增 `Kind` + `global` 知识库**：把记忆降级为知识库，复用外键与库范围，但采集目标、权限和检索语义都会把记忆当成普通知识；也无法表达快照发布与提示注入；否决。
- **每项目各存一份**：跨项目不共享，必然重复与漂移，与目标相反；否决。
- **在 `kb_nodes` 增加 `scope` 字段**：id 规则、索引、写入校验和对外契约都要改，改动面最大，而记忆仍需要独立生命周期；否决。
- **在会话抽取时顺带产出方法论**：单会话看不到趋势，产出的是总结而非准则，会制造伪方法论；否决。
- **聚合任务也注入记忆**：形成自证循环，准则会用自己的产出证明自己；第一期否决，后续引入前必须先有影子抽取对照。
- **提炼后立即生效**：半成品会马上影响生产抽取，回滚只能事后补；否决。
- **以原始会话为主证据**：证据最原始，但每周重读全部会话的 token 成本不可控；第一期以 canonical 节点为主，原始会话抽样核对列为后续里程碑；否决作为第一期主路径。

## 后果

- 新增记忆域表、Alembic 迁移与 `kb` 运行角色的表权限；新增周期聚合任务与调度入口；抽取提示组合方式变化；`kb_write_audit`（或等价审计）增加「所用记忆版本」字段。
- 抽取行为会随记忆版本变化，对照历史结果必须按快照版本解释；影子抽取（无记忆对照）暂未实现，闭环质量在第一个版本里不可量化，这是已知限制。
- 成本：每周一次聚合 LLM 调用，加每次抽取因 top-k 注入增加的少量 token；需要预算上限与按项目的注入开关。
- 记忆是本部署全局共享，一条错误准则会跨项目放大；靠证据门槛、版本回滚、人工废弃与冻结控制，聚合任务不得覆盖人工裁决。
- 实施前仍需在规格阶段定：表名与字段、门槛数值、快照发布/回滚的操作入口、MCP 是否增加只读工具、管理台页面形态。ADR 只裁决方向与边界，不写死这些实现细节。
