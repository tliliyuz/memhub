# ENVIRONMENT_CONVENTIONS — 环境变量与密钥约定

| 适用范围 | 敏感值的键登记、本机落盘与按名引用 |
| 不负责 | 具体键名与读取方清单；见各仓的 `docs/tech/ENVIRONMENT.md` |

本文件约束敏感值从「被提供」到「被引用」的完整路径：值属于长期项目事实，必须在
同一会话落到本机 `.env`，之后只按名引用，不随会话或命令消失。配置键见
[治理配置契约](../contracts/governance-toml.md)。

## 1. 键登记

- 每个环境键必须同时出现在 `.env.example`（键清单）与 `docs/tech/ENVIRONMENT.md`
  （键名、读取方与失败语义），两处键集由 `env_keys` 双向比对。
- `.env.example` 只写键名与空值或占位说明，不写真实密钥；密钥值不进仓库、文档与
  提交信息。

## 2. 值落盘

- 值无论从何而来（负责人口述、peer 提供、外部文档），同一会话内把 `键=值` 写入
  本机 `.env`；`.env` 缺失则创建。值未知先留空，不猜测，也不沿用其他键的值。
- `.env` 是被指定且 Git 忽略的持久落点；写入 `.env` 不违反「密钥不进仓库」。
- 写入后只按名引用：不把字面值重复带进命令、不留在会话，也不写入知识库或任何
  Markdown。换会话时从 `.env` 按名取值。

## 3. 本机校验

- `env_keys` 在本机 `.env` 存在时要求其键集覆盖 `.env.example` 声明的全部键：
  键行必须存在，值可为空。
- `.env` 不存在（新克隆或 CI）时跳过本地侧，只比对 `.env.example` 与
  `ENVIRONMENT.md`；`env_local` 配置键可改本机文件路径，默认 `.env`。
