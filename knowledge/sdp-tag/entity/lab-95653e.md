> 离线调参与评测入口模块（TagLabServiceImpl / LabBatchPlanner），其链路本身是低效与超时的来源之一。

# 定义

kind: module

实验台（lab）是打标系统的离线调参与评测入口，承载 A/B 实验、阈值扫描、评测回放等能力，主要实现为 `TagLabServiceImpl`，批次规划由 `LabBatchPlanner` 承担。

# 关键属性

| 属性 / 组件 | 说明 |
| --- | --- |
| `maxBatchRetries` | **硬编码为 0**（B7），一次 429 即整件重来 |
| `LabBatchPlanner` | 对**估算超过 64k 的语义组**切成最少的连续子请求；正常组一个语义组一个请求（B10） |
| 图片地址选择 | 仍**优先 `origin_url`** 而非 `store_url` → [[OSS/COS 图片转存]] 并未解决 lab 的图片下载超时（B11） |
| `run-timeout` | 曾默认 10m，截断后留下「部分结果」却回调 success（B9）；线上现设 **30m** |
| `lab_accuracy --reuse-baseline` | 复用旧判定做历史对比，但**输入指纹不同会拒绝复用**（F7） |
| 测试资产 | `labRecordStore.test.ts` 因 `fake-indexeddb` 声明未安装而**永远失败**（G18）；2 个测试因别名排除未同步失败（G19） |

# 关系

- → [[打标引擎（TagEngine）]]：核心逻辑从 lab 抽取到引擎，合并后需 diff 移植（D15）。
- ↔ [[Judge 判定模型]]：lab 是评测执行者，判定口径由 Judge 提供。
- ↔ [[消息队列 / 阿里云 Serverless AMQP]]：lab 也会消费队列，`maxBatchRetries=0` 与「无 DLX」叠加放大损失。
- ↔ [[维度图谱（graph）]]：评测基线依赖图谱快照，图谱漂移会污染实验（F6/F7）。
- ↔ [[幂等键与缓存指纹]]：`tagged_input_hash` 为 NULL 时 lab 与正式链路都会全量重打。

# 已知问题

- ⚠️ 取消维度阶段的收益**从未被测量**（G15）——无法回答「这个改动值不值」。
- ⚠️ 优先 `origin_url` 造成的图片下载超时未解。
- ⚠️ 既有测试失败（G18/G19）与 `vue-tsc` 既有错误（G20）使得「测试/类型检查通过」不能作为干净判据。
