> 维度、标签取值与补全关系的权威数据源，其数据错误与评测期间的漂移是打标准确率的主要外因。

# 定义

kind: platform

维度图谱是维度、标签取值（含父类取值）以及标签间补全关系的**权威数据源**，归属图谱团队维护。打标模型的可选空间与 [[Judge 判定模型]] 的判定依据都由它决定。

# 关键属性

| 属性 | 说明 |
| --- | --- |
| 父类取值 | 图谱里父类**本来就是合法取值**，且 [[图谱补全]] 依赖它们（A1 中 68 条被判死的「父类标签」实际合法） |
| 数据错误示例 | 「设计师合作IP」维度挂的是 `snglss` / `shrt` / `jckt` 这类**品类缩写**，不是真实 IP 名（A5） |
| 规模变化 | 标签 6,352 → 7,440（+17%），新加 1,088 个标签不在冻结基线分母中（F6） |
| 定义改写 | 图谱团队 10-26 09:21 重写 **140 个维度定义**；10-23 改过一个维度定义并给 `attr5` 开开关（F6） |
| 补全质量 | 121 条图谱补全**只有 36.4% 正确**，贡献 77 条错误（17.8%）（A7） |

# 关系

- ↔ [[Judge 判定模型]]：判定依据来自图谱取值。
- ↔ [[维度定义]]：排他式定义与图谱既有取值冲突 → −7.3pp、服装 −31pp。
- ↔ [[图谱补全]]：补全只向上不向下、不检查直判否定、恒零收益的同义补全。
- ↔ [[打标评测方法论]]：做历史对比必须显式对齐图谱（内存还原 / 冻结快照 / 凭证复用）。

# 对齐手法（F7）

1. **内存还原**：`BeanPostProcessor` 代理 `GraphDimensionMapper` 还原旧定义；代理 `ITagFieldConfigService.listMerged` 去掉 `attr5`。
2. **冻结快照**：从基线导出的 `graph` 块还原变更行。
3. **凭证复用**：`lab_accuracy --reuse-baseline` 复用旧判定，**输入指纹不同会拒绝**。

# 归属边界

按 `01-术语实义.md`（待入库）第 3 节的图谱归属边界，图谱数据错误（如 IP 维度挂品类缩写）属于**交给图谱团队**处理的事项，打标侧无论定义怎么写都救不了——只能下线/修标签。
