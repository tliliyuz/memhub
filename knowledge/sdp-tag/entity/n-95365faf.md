# 打标服务

## 定义

线上打标的正式链路，配置前缀 `tag.pipeline`。接收 MQ 事件 → [[场景]] 门禁 → 标签判定 → 通过 [[对方 search 服务]] 回写。

## 关键属性

- **label 阈值 0.9**（`tag.pipeline.label-threshold`），与实验台的 0.7 不同，见 [[阈值体系]]。
- 阶段为 [[打标阶段模型|scene → label]]，无独立维度阶段（2026-10-26 `69f77f1` 删除）。
- `deploy/k8s/api.yaml` 的 env **没有覆盖阈值**，改阈值需走配置而非部署清单。
- 服务端筛分（模型不筛），比较字段统一为 `TaggingDecisionDTO.score`，见 [[TaggingResultUtils]]。

## 关系

- 与 [[打标实验台]] 成对：实验台结论**不可直接搬到**线上。
- 产出标签属 [[知识图谱]] 的行业资产语义，见 [[标签]]。
- 回写动作成本几乎为 0，见 [[重跑动作体系]]。

## 易误解

- 线上 0.9 与实验台 0.7 的差异会同时改变 [[分数带与准确率]] 的取值区间，跨环境比较准确率数字无意义。
- 「回调成功」只代表 HTTP 通了，落库是对方动作。
