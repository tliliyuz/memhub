> 版本化的打标提示词产物（label v3/v4/v5.1/v11），每加一条全局规则都会跨标签溢出并拉长单题 token。

# 定义

kind: other

打标提示词是版本化的产物（label v3 / v4 / v5.1 / v11），承载打标模型的通用判断协议与规则。其版本演进线是「全局规则引发跨标签副作用」的教科书案例。

# 关键属性

| 版本 | 加了什么 | 副作用 |
| --- | --- | --- |
| label v3 | 长规则手册（4 通用 + 3 判定口径） | 婴童从 0.53~0.68 涨到 0.70~0.88，5 个 KID 商品全部误打；tokens **+62.6%** |
| label v4 | 「KID/儿童不证明婴儿或婴幼儿」 | **打破儿童本身**：3 个 KID 化妆品儿童分从 0.96/0.89 掉到 0.69/0.46 |
| label v4 | 「少量不等于主要或纯纺」 | 100% 棉 T 恤棉分 0.76 → 0.66 |
| label v5.1 | 加材质条款 | 人造棉升到 0.73，暴露错误关系 `人造棉 -belong-> 棉质` |
| label v11 | 长度膨胀 | 单题约 **341 字符**，估算 81,317 token → 触发 64k 超限，314 题失败 |

# 关系

- ↔ [[语义安放]]：根因是 4,692 个标签的 `remark` 100% 为空，语义无处安放只能往提示词塞全局规则。
- ↔ [[打标引擎（TagEngine）]]：提示词长度直接决定批次拆分与 token 成本。
- ↔ [[实验台（lab）]]：超限组由 `LabBatchPlanner` 切成最少连续子请求（B10）——「一个语义组一个请求」与「超限自动拆分」不矛盾。
- ↔ [[维度定义]]：语义应进标签备注 / 维度定义，提示词只留通用判断协议。

# 教训

- **先算真实提示词版本的长度，再怀疑图片**（B10）：314 题失败的根因是 label v11 的字符数，早期「62k + 1.5k 图片」的猜测是错的。
- 全局规则**必然**跨标签溢出，不存在「只影响某个维度」的全局规则。
