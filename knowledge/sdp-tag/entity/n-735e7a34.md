> 商品标签知识图谱（graph），由四张图谱表构成的打标语义底座，提供维度定义、标签备注、标签关系与分维阈值；既提供补全路径的数据来源，也是数据质量问题的集中地——4,692 个标签 remark 全空是图谱问题清单与提示词膨胀的共同根因。

# 定义

标签图谱（商品标签知识图谱，graph）是标签之间的结构化知识库：既提供标签间推导（补全），也是数据质量问题的集中地。在打标系统中它充当**语义底座**，用四张表承载维度定义、标签备注（`remark`）、标签之间的关系（父子 / 近义并存）以及 `graph_dimension.label_threshold` 分维阈值。

# 关键属性

| 属性 | 值 |
| --- | --- |
| 结构性问题 | **4,692 个标签的 `remark` 全空（100%）**——图谱问题清单的根因，也是提示词被迫膨胀的根因 |
| 组成 | 四张表：维度定义、标签备注（`remark`）、标签关系（父子 / 近义并存）、`graph_dimension.label_threshold` 分维阈值 |
| 分维阈值 | 挂在 `graph_dimension` 表上，随 `TagTaskRunSpec` 快照一起走，见 [[阈值挂图谱表]] |
| 指纹分流 | 阈值进 `configHash`（改阈值 → 全量缓存失效）、不进 `graphHash`（改阈值不翻转图谱指纹） |
| 版本 | 召回口径涉及「冻结图谱版本」（见 [[仲裁口径]] 规则 4）；导出时 `version` 取四张表 `max(update_time)` |
| 导出 | 全量导出按行业嵌套、不拍平，见 [[图谱导出接口]] |
| 问题清单规模 | 8 项（2026-10-20） |
| 诊断数据 | 55.6% 的错误可归因到定义 / 图谱缺陷 |

# 图谱问题清单（8 项）

10-20 建立的清单中，根因项是「4,692 个标签的 remark 全空」；其余 7 项本文未展开，需后续来源补充。

该空 `remark` 的直接后果是提示词被迫膨胀，见 [[提示词短协议原则]]。另一项结构性事实：**父子与近义取值本来就并存**，因此任何「排他条款」都会被 judge 按字面执行并反噬准确率（−31pp 根因），见 [[定义编写原则]]。

# 在数据流中的位置

```
直标命中 ∪ 图谱补全 = 最终标签
```

补全标签**没有分数、任何阈值管不到**，准确率天然低 4~5pp（36.4% vs 93%，贡献 17.8% 的错误）。详见 [[补全路径]]。
