> sys_config → env → yaml 三源优先级；Redis 按租户缓存需 HDEL 才生效；tag_field_config 无 ON UPDATE CURRENT_TIMESTAMP；secretKeyRef 用 .value 打印为空。

# Definition

配置从三个来源解析，优先级为 **`sys_config` → env → yaml 默认**。改配置「不生效」有四种可能，且都不报错（[[静默失败]]）。

# 四种不生效的可能

| # | 现象 | 原因 / 解法 |
| --- | --- | --- |
| ① | `update_time` 没动 | `tag_field_config` **没有 `ON UPDATE CURRENT_TIMESTAMP`**，裸 SQL 不刷新（看起来像「本来就配了 0」）；自定义 `updateTask` lambda 同样不刷新 |
| ② | 值是空的 | 该项是 `secretKeyRef` —— `-o jsonpath='{…env[*].value}'` 打印为空；应打印 `name`：`{range …env[*]}{.name}={.value}{"\n"}{end}` |
| ③ | MySQL 改了没用 | `sys_config` 按租户缓存为 `<tenantId>:sys_config` hash，**必须 `HDEL` 那个字段** |
| ④ | 优先级搞错 | 三源优先级：`sys_config` → env → yaml |

# 相关配置陷阱

- **环境变量名**：`tag.image-fetch.allowed-hosts` → `TAG_IMAGEFETCH_ALLOWEDHOSTS_0`（连字符去掉），写错静默失效。
- **端点分离**：[[snailjob]] 的 `server.*`（gRPC）与 `openapi.*`（HTTP）是两个独立配置。
- **Worker 只读快照**：`run_spec_json.configurationError` 说明改配置救不了已建任务（[[tag_task]]）。
- **前端**：`VITE_APP_ENCRYPT=false` 写 `.env.development.local`，**改 env 必须重启 vite**。
