> md5（注意滚动更新打到旧 pod）+ imageID（ACR 存 OCI index，缺 Accept 头会误报 MANIFEST_UNKNOWN）+ 前端入口 hash。

# Definition

判断「新版本是否真的在跑」的三步校验。

| 步 | 命令 | 判据 |
| --- | --- | --- |
| 1 | `kubectl exec <pod> -- md5sum /sdptag/server/app.jar` | 与本地构建 jar 的 md5 一致 |
| 2 | `kubectl get pod … -o jsonpath='{.items[0].status.containerStatuses[0].imageID}'` | 与推送摘要 `sha256:…` 一致 |
| 3 | 前端入口 `/assets/index-XXXX.js` | 与本地 `dist` 的 hash 一致 |

# Significance

每一步都有真实踩过的坑：

- **滚动更新打到旧 pod**：「第一次校验取到的是旧 pod」，md5 对不上先确认 pod 名。
- **ACR 存的是 OCI index**（linux image + attestation）：验证脚本若不带 `Accept: application/vnd.oci.image.index.v1+json`，会**误报镜像不存在**（`MANIFEST_UNKNOWN`）。
- 前端 hash 是唯一能证明静态资源已更新的证据（见 [[sdp-tag-web]]）。
