> H/I/C 三维指纹定义何时复用、何时 stale；tagged_input_hash 为 NULL 会导致全量重打，每件约 18.7 万 token。

# 定义

幂等键与缓存指纹决定「同一条商品再次推送时能否复用已有打标结果」。现行方案使用 **H/I/C 三维指纹**：

- **H**：外部输入（如价格、销量）等业务字段；
- **I**：真正进入 prompt 的值；
- **C**：配置（提示词版本、维度定义、阈值等）。

# 重要性

指纹错误直接转化为 token 成本与数据一致性风险。`tagged_input_hash` 为 **NULL** 会让缓存永远命不中——「今天用旧代码打完的商品，明天对方一推同样的商品，会被原样重打一遍」，每件约 **18.7 万 token**（D1）。

# Schema：规则与后果

| 规则 | 后果 |
| --- | --- |
| H 外输入（价格类）变化 → **只标 stale，不自动重打** | 结果可能过时，但不会触发天量重算（方案 B「调价即重打」≈ 8 亿 token/次 已被否） |
| 存量成功结果**没有 I** → 一律 stale | 升级后首轮全量重打风险 |
| 幂等键**不含品牌**（G4） | 两品牌 SPU 重叠时后到者被静默跳过（静默失败） |
| `recover-url` 无品牌级覆盖（G5） | 多品牌只能共用一个地址 |
| `run_spec_json` 存了 `configurationError`（G11） | 改配置救不了已建任务 |

# 被推翻的价格方案（A8）

| 方案 | 问题 |
| --- | --- |
| B：调价即重打 | 约 8 亿 token / 次 |
| C：缓存串 | 标签与价格脱节 |
| D：规则打标（正解） | **引擎没实现**（有 `rule_tagger_code` 字段但无执行） |

另：把 price / discountPrice / sales 的 AI 开关置 0 的旧做法已被 H/I/C 方案作废。

# 运维含义（D1）

「等队列跑空再发版」是**反的**——旧代码写的 `tagged_input_hash` 为 NULL，越晚发版，被旧代码打过的商品越多，第二天会被原样重打。正确做法是**立刻停**。见 [[运维与发版规范]]。
