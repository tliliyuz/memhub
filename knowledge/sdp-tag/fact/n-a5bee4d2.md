> 商品打标评测中反复踩到的四个高频错误：混比 rubric、把砍标签抬高的准确率当改善、忽略补全路径、把实验台阈值当线上阈值。

# 定义

评测口径陷阱指本项目在度量准确率与效果时反复出现的四类系统性误判。按踩坑次数排序，它们是团队复盘时的第一条检查清单。

# 错 1：拿不同 rubric 的准确率直接比

strict 68.2% 和 inference 88.0% 是同一批数据 `[Z]`。**混在一列里就是错的。**

历史数字（Zara 79 baseline、RL 各版）**全部是 strict**（`lab-accuracy-v2`）；2026-10-27 之后官方默认改为 inference（`lab-accuracy-v3-inference`）。详见 [[判分口径]]。

# 错 2：把「砍标签抬高的准确率」当成改善

准确率分母是**已产出的标签对**，砍掉判对的标签同样会抬准确率。

评估任何「少打」类改动，必须同时给出**三件套**：

1. 保留集准确率
2. 被砍集的准确率
3. 被砍标签的复核结论

这条团队踩过两次。

# 错 3：忽略「补全」这条路径

最终标签 = 直标命中 ∪ 图谱补全。补全**没有分数、任何阈值管不到**，因此：

- 算错误率必须分直标/补全（曾因混算得出偏差结论）；
- 「支持数 / 最终标签数」的 90% 不等于模型判了 90%；
- 补全准确率天然比直标低 4~5pp `[D]`，实测 36.4% vs 93%（补全贡献 17.8% 的错误）`[Z]`。

详见 [[补全路径]] 与 [[标签图谱]]。

# 错 4：忘记「实验台阈值 ≠ 线上阈值」

| 场景 | label 阈值 |
| --- | --- |
| 实验台 `tag.lab.label-threshold` | **0.7** |
| 正式链路 `tag.pipeline.label-threshold` | **0.9** |
| 历史 doubao 方案 | **0.999** |

而且 `deploy/k8s/api.yaml` 的 env **没有覆盖阈值**——改 yaml 不会改阈值。详见 [[阈值分层]] 与 [[TKE 集群]]。

# Significance

这四个错误是 [[仲裁口径]] 规则 4（数字冲突先查分母口径）的现实来源；也是 [[引用标注规范]] 要求四要素的直接动因。
