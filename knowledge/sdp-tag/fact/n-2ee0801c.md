> 标签 remark 全为空导致语义只能往提示词堆全局规则，而全局规则必然跨标签溢出；正解是语义进备注/维度定义。

# 定义

语义安放指「一条标签的语义应该存放在哪里」的设计问题。可选的载体有三处：标签 `remark` 备注、[[维度定义]]、[[打标提示词（label 版本）]] 内的全局规则。

# 重要性

它解释了整条提示词演进线的**根因**：数据模型没有给语义留位置，规则就必然堆积在提示词里，而提示词是**全维度共享**的。

事实：4,692 个标签的 `remark` **100% 为空**。

# 因果链

```
remark 空 → 语义无处安放 → 只能写进提示词全局规则 → 全局规则跨标签溢出 → 修 A 维度坏 B 维度
```

具体副作用（A6）：

- label v3 长规则手册 → 婴童分数整体上移，5 个 KID 商品全部误打，tokens +62.6%
- label v4「KID/儿童不证明婴儿或婴幼儿」→ 打破儿童本身（0.96/0.89 → 0.69/0.46）
- label v4「少量不等于主要或纯纺」→ 100% 棉 T 恤棉分 0.76 → 0.66
- label v5.1 材质条款 → 暴露错误关系 `人造棉 -belong-> 棉质`
- label v11 → 单题约 341 字符，估算 81,317 token，触发 64k 超限

# 正解

1. 提示词只保留**通用判断协议**；
2. 语义放进**标签备注 / 维度定义**；
3. 修图谱关系（错误关系是数据问题，不是提示词问题）。
