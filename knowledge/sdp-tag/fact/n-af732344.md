> 28 条打标系统方案决策日志，逐条记录「选了什么 / 放弃什么 / 为什么 / 代价」，并标注已被推翻的结论。

# 概述

本文是一份**方案选型与权衡决策日志**，共 28 条，每条按固定格式记录：**选了什么 / 放弃了什么 / 为什么 / 代价是什么**。覆盖主题包括提示词演进、四段结构协议、分维阈值与门控、请求批量组织、两阶段流程、幂等与回调、judge 模型与阈值、部署资源与镜像发布、架构与文档规范。

文档最有价值的两类信息：

1. **「代价」栏与根因洞察**——例如 4,692 个标签 `remark` 全空，导致提示词被迫累积全局规则；`run_spec_json` 把 `configurationError` 一起固化；`sys_config` 改了 MySQL 不会生效（需先 `HDEL`）。
2. **事后被推翻的结论**——分维阈值的收益、补 13 个维度定义，均在后续实测中转为净亏，推翻关系指向 [[03-失败与被推翻]]。

# 关键洞察

- **根因洞察（提示词膨胀）**：4,692 个标签的 `remark` 100% 为空 → 标签语义无处安放 → 提示词被迫累积全局规则 → 全局规则产生跨标签副作用，修一处坏一处。正确解法是**修图谱关系而不是加条款**，详见 [[提示词短协议原则]] 与 [[标签图谱]]。
- **能力 vs 默认值**：「每个维度一个最佳阈值」是**能力**，不是自动生效的**默认**。把一次实验得出的最佳值写死，等于把噪声固化成结论（[[分维阈值：能力而非默认]]）。
- **配置指纹的两条陷阱**：新字段必须 `@JsonInclude(NON_NULL)`（否则升级瞬间全量重打）；阈值字段用 `Double` 不用 `BigDecimal`（`JacksonConfig` 全局 `ToStringSerializer`）（[[阈值挂图谱表]]）。
- **门控的三重损失**：分数（92.7% 被抹成 0）、失败可观测性（39.3% 批次整批零输出且不可区分）、离线调参（实验台面板失效）（[[模型门控 vs 服务端阈值筛选]]）。
- **语义放对位置**：颜色类语义应锚定标签备注/维度定义的**文字字段**，而不是靠图片（[[图片始终发送]]）。
- **架构决策程序化**：先落地后补测量，会让「值不值」永久无法回答（[[架构决策先落地后补测量的流程问题]]）。

# 已被推翻 / 已被否定的结论

| 结论 | 当时的依据 | 后来的实测 | 现立场 |
| --- | --- | --- | --- |
| 分维阈值优于纯全局阈值 | 全局 0.90 牺牲 1,503 条正确标签，分维只牺牲 487 条 | 19 个分维阈值 16/19 净亏，每砍 7 条正确标签才换 1 条错误，且账在噪声内 | 「有能力但别动」 |
| 补 13 个维度定义 | 标签名自带语义，只补高分误判与判不出 | 13 维定义 −7.3pp，品类 −31pp | 「定义怎么写比写多少重要」 |
| doubao 0.999 为首发生产 judge | 0.7 = 65.2%，0.999 = 80.1% | qwen3.8-flash 0.9 = 92.4%（79 件） | 模型与阈值已切换 |
| 定义可写排他条款（父子互斥等） | — | 与图谱并存的父子/近义取值打架，−31pp | 禁止排他条款 |
