> dimension_definition 的写法规范——描述性规则有效，排他式条款与图谱既有取值冲突必致负收益。

# 定义

维度定义（`dimension_definition`）是为某个打标维度补充的判定规则文本，进入提示词影响模型输出，同时影响 [[Judge 判定模型]] 的判定口径。

按写法可分两类：

- **描述性规则**：什么算、什么不算、修饰词不作依据。
- **排他式条款**：「父子互斥 / 同档互斥 / 只打最细层级」。

# 重要性

定义是**唯一同时影响双方口径**的杠杆：模型是否照做、Judge 是否照判，任何一侧不一致都是负收益。

| 实验 | 结果 |
| --- | --- |
| 13 个维度补**排他式**定义 | A 路 90.9% vs B 路 **83.6%**；服装 95% → 64%（**−31pp**）；矛盾数 25 → 150 |
| 材质**描述性**定义 | **+3.4pp** |
| 开合方式**描述性**定义 | **+9.4pp** |

排他条款失败的原因是**跟图谱的既有取值打架**：模型照样打出父类，Judge 按新规则判死；而图谱里这些父类本来就是合法取值，[[图谱补全]] 也靠它们（A1 中 68 条即属此列）。

当前状态：`dimension_definition` **非空 0 行**，全部回滚。

# 常见主题

## 定义来源纪律

- **不得用样本反推规则**：用户明确否掉「拿这 100 个样本穷举倒退模型输出」（A3）。换品牌即失效，还会把 prompt 撑成案例集。
- 正解：定义只写描述性规则 + **合成**反例；样本数字只作依据，不进定义。此条已进入 `docs/项目开发规范/refs/评测工作规范.md` 第 3.7 条（待入库）。

## 命名与描述纪律（元错误）

2026-10-26 那批实验里 DB 中 141 个 `dimension_definition` **全是 NULL**，所谓「精简版」只存在于 10-26 19:09 → 10-27 12:06 窗口；实验实际跑的是**定义被清空**。因此第三个 cohort 必须叫「定义清空」，不能叫「精简版」，否则后续所有引用都会错（A9）。

## 与语义安放的关系

语义应放在**标签备注 / 维度定义**，提示词只留通用判断协议（见 [[语义安放]]）。
