> 命中复用需 contentHash / configHash / inputHash 三者同时相等；另有 graphHash、promptSha256、origin_url_hash 等语义哈希。

# 指纹与哈希复用

## 定义（实义）

「指纹」不是一个 hash，而是**至少五个语义不同的哈希**。说「指纹」时不区分，是最大误解源 `[D]`。

### 复用判定三元组（三者同时相等才复用）

| 哈希 | 覆盖什么 | 什么时候变 |
| --- | --- | --- |
| `contentHash` | 商品文本字段 + 图片列表 | 商品内容变了 |
| `configHash` | 整个 `TagTaskRunSpec`（**含图谱快照里的维度阈值**） | 调阈值 / 改 prompt / 换模型 |
| `inputHash` | 真正送进模型的输入（含主图标识） | 输入变了 |

### 语义哈希（不参与三元组判定）

| 哈希 | 覆盖什么 |
| --- | --- |
| `graphHash` | 图谱快照（含维度定义，**不含阈值**） |
| `promptSha256` | rubric 变化 |
| `origin_url_hash` | 归一化 URL（去掉 `?` 与 `#` 之后）的 sha256 `[Z]` —— 同一张图换 CDN 参数就是不同指纹 |

## 最容易踩的一条

> `configHash` 是对**整个 `TagTaskRunSpec`**（含图谱快照里的维度阈值）做 SHA-256。**你一旦调了某个维度的阈值，configHash 就变了** → 这批商品再推 MQ 不会复用旧标签，而是重新打标。

**调一个维度阈值 = 全量缓存失效。** 见 [[阈值体系]]。

## 字段名陷阱

- `message_digest`：原始报文摘要（后降级为审计）。
- `content_digest`：解析后规范化内容摘要。
两者名字相近但语义不同。

## H/I/C 分层与 stale

`[Z]`：价格类字段仍在 H 外，但进入 prompt 的值由 I 保护 → **改价不会触发重打，只标 stale**。

- 存量成功结果**没有 I**（`tagged_input_hash` 为空）→ 一律 stale，等显式触发才重跑，见 [[重跑动作体系]]。
