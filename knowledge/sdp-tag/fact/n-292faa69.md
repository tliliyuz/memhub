> 采集成功判据、干净 A/B、三评协议、噪声基线先行、口径一致性——打标实验的可信度框架。

# 定义

打标评测方法论是判定「一次改动是否真的有效」的规则集合，覆盖采集、对照、判定、统计口径四个环节。它被列为「最容易被低估」的一类知识。

# 重要性

绝大多数「收益」在噪声、脏数据与口径漂移中被放大或反转。缺少方法论时，团队会反复在同一份数据上得出互相矛盾的结论（见 [[分维阈值与准确率口径]]）。

# Schema：核心规则

| # | 规则 | 反例与后果 |
| --- | --- | --- |
| F1 | **采集成功判据**：`failedBatchCount == 0` 且 label 阶段非 `failed|skipped` 且标签数 > 0 | 只判 HTTP 200 → 7 件 0 标签坏数据混进分母，抬高准确率 |
| F2 | 禁止用样本反推 Prompt / 写排他条款 | 已写进 `docs/项目开发规范/refs/评测工作规范.md` 第 3.7 条（待入库） |
| F3 | **干净 A/B**：基线也过一遍完全相同的三评协议，只差「定义有没有进 prompt」 | 拿新旧口径的两批数字直接比 = 混了两个变量 |
| F4 | 不用 `support/(support+contradict)` 当准确率 | 那只是剔除弃权 |
| F5 | **口径一致性** | coverage 用 `>=` 而链路用 `>` → 边界值判反；`TagTaskSpecFactory:55` 硬编码 0.8；部署清单与集群 tag 漂移 |
| F6 | **图谱冻结**：历史对比前确认图谱未变 | 标签 6,352 → 7,440，新加 1,088 个标签在分母里根本不存在；图谱团队重写 140 个维度定义、给 `attr5` 开开关 |
| F7 | **显式对齐图谱** | 内存还原 / 冻结快照 / `--reuse-baseline`（指纹不同会拒绝复用） |
| F8 | **假阳性纪律**：先抓 `Content-Type` + magic bytes，再归因 CDN 内容协商 | 「ZARA CDN 无 Accept 返回 WebP」用五种 header 变体实测**全部 image/jpeg**，无法复现 |
| E12 | **先测噪声基线** | 同配置重跑 Jaccard 0.680，精确账落在噪声内 |

# Examples

- **门控实验（B1）**：门控省 66% 输出，但共同 3,179/94.5%、门控丢失 1,159（899 正确 / 77.6%）、新增 406（230 正确 / 56.7%）——用「少 671 条正确标签」换「少 27 条错误标签」，交换比不好看。
- **noul-only（B2）**：预期去掉 `reason` 能省大量输出，实测**只省 10%**，模型把字数转成隐藏推理（72.5 → 58.5），设想被证伪。
- **三评协议下的归一化对比（F3）**：只有基线也走同一协议，「定义有没有进 prompt」才是唯一变量。
