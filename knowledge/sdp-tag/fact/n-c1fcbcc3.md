# 概述

本文件是一份**失败知识**文档，对象是一套电商商品 AI 打标系统（维度定义、标签、提示词、[[Judge 判定模型]] 判分、评测、消息链路、部署运维）。它与仓库里「现在是怎么做的」文档互补：仓库只写现状，本文件写**为什么不那么做**。

# Schema

每条记录的统一格式：

- **试了什么** — 当时的假设与做法
- **结果** — 可量化的观测（准确率 pp、token、条数、死锁率等）
- **根因** — 机制层面的解释
- **现在的做法** — 回滚 / 替代方案
- **代价** — 遗留成本或未修缺口

两个标记约定：

- **⚠️** 表示**当前仍存在的缺口**，不是历史教训。
- 出处分级：`[C]` Codex 会话导出、`[D]` DSH 会话导出（11 月权威）、`[Z]` zcode 记忆（10-19~11-02 权威，本文贡献最大）；逐条原文见 `evidence/`（待入库）。

# 核心主张

1. **失败知识的价值高于现状描述**，因为后者不解释「为什么不那么做」。
2. 多数事故不是能力问题，而是**归因错误、静默失败、噪声与口径不一致**四类系统性错误：
   - 归因错误：把 [[Judge 判定模型]] 的 `pairs-evidence.evidence` 当模型理由（A4）；把 [[维度图谱（graph）]] 的数据错误当定义问题（A5）；把「精简版定义」当成描述对象（A9）。
   - 静默失败：见 [[静默失败]]，横跨 HTTP 200 假成功、空 `tags`、部分结果、无 DLX。
   - 噪声：同配置重跑 Jaccard 0.680，精确账落在噪声内（A2）。
   - 口径不一致：coverage 用 `>=`、链路用 `>`；`TagTaskSpecFactory:55` 硬编码 0.8（F5）。
3. **先证明现象是缺陷，再找根因**（D14 四处误判的共同病灶）。

# Examples

文中若干最具迁移价值的单点：

- **A1**：13 个维度的排他式定义 → 服装 95% → 64%（−31pp），因为排他条款与图谱既有取值打架；描述性规则才有效（材质 +3.4pp、开合方式 +9.4pp）。
- **A2**：19 个分维阈值净亏 −395（丢对 491 / 丢错 96）；二次推翻发现被砍的 122 条里 79.9% 本来是对的。
- **B3**：并发 1 → 10，30 秒内 57 条真实商品消息全失败并转死信；503 是网关通道冷却，不是模型下线。
- **B5**：假定队列有 DLX 可重放 → 实际未配 `x-dead-letter-exchange`，消息被 broker 直接丢弃，57 条真丢。
- **C6**：只判 `response.isOk()` = 假成功，对方业务失败仍返回 HTTP 200（body `code=400`）。
- **C7**：`tags: []` 的那条**一次模型调用都没发**（`grep -c "LLM 判断请求"` 两小时为 0），空结果产生在 judge 之前。
- **D8**：完成路径加 `FOR UPDATE` → 28% 死锁；非锁定读 + `DeadlockRetry` 后 0%，但 `recoverTenant()` 一事务处理整批未改。
- **F6/F7**：图谱在评测期间被改写（10-26 重写 140 个维度定义、`attr5` 开开关），历史对比必须显式对齐。
