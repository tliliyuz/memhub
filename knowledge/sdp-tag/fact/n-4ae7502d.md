> 模型输出全部候选分数、阈值筛选放服务端，换取分数可得性、失败可观测性与 5 秒离线调参。

# 定义

两条路线在「谁做阈值筛选」上分歧：

- **模型门控**：让模型自己按阈值裁掉低分候选，只输出通过的标签。
- **服务端筛选**（选定）：模型输出**全部候选的分数**，阈值筛选全部放在服务端。

# 意义（为什么选服务端）

> 「离线调参直接废掉……让模型自己门控，改阈值 = 改提示词 = 必须重跑打标。」

成本对比：全量重打 100 件 = **1,130 万输出 token / 1.5 小时**；离线扫阈值 = **5 秒**。

# 门控的真实代价（三条）

1. **丢掉分数**——92.7% 的分数被抹成 0。
2. **丢掉失败可观测性**——39.3% 批次整批零输出，且与「模型没干活」**不可区分**。
3. **丢掉离线调参**——[[Lab 实验台]] 的分维阈值面板对门控运行**完全失效**。

另加：门控下输出分数整体上移 **+0.058**，阈值语义被改写。

# 代价（选定方案的代价）

输出 token 花得多（门控能省 66%）。团队选择接受，把这个钱转投到零语义风险的 [[短题号别名]] 优化上。
