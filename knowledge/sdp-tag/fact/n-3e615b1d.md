> 交付文档用中性口吻；HTML 周报要 PPT 式一屏一页、封面不放指标、删除口号式标题；新结果折进对应章节。

# 定义

项目内关于交付文档与汇报材料的一组硬性风格约定。

## 1. 交付文档口吻：中性

- **不提「我方/对方/你们/合作方」**，只按角色描述。
- 来源是一次真实批评：「我上次才把这个文档改为中性的，你又开始加第二第三人称干啥」。

## 2. HTML 周报风格

**要**：PPT 式幻灯片、一屏一页、scroll-snap 翻页 + 方向键 + PageUp/PageDown + 侧边点 + 页码；打印一页一张 16:9；超大页自动缩放。

**封面**：**不放指标**，放两个样本（RL 100、Zara 79）的短描述 + 场景分布 + 子品牌 + 图片尺寸。

**不要**：

- 不说「真实」，不重复场景列表已经显示的百分比
- 不要「用途」行（两个样本都用于所有对比）
- 不写「Zara 等」（都是单品牌）
- **删除**：口号式标题、英文装饰标签、页面文字里的 git commit hash、证据/口径页、`[n]` 引用标记、「未完成」/下一步、含糊括注（「（未真实重跑）」）

## 3. 框架准确率的表述

- Zara 是**场景均衡样本**（覆盖 7 个场景）；RL 是自然场景分布，更接近线上数据。
- ⚠️ **不能说 RL 是「随机抽取」**：它是从最先转存的 245 件里分层抽样 + 17 次置换；要叫随机得从 4,687 件重新抽。见 [[评估样本集]]。

## 4. 文档结构

新结果要**折进对应章节**：设计章放方法、结果章放数字、摘要表放头号指标、结论章放 takeaway；**不要在文末追加一个带日期的「## N. 新测试」章节**。
