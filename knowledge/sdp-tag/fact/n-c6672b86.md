# 环境变量宽松绑定规则

## Definition

> Spring 宽松绑定：**点换下划线、去掉连字符、大写**。
> `auto-tagging.rabbit.run-timeout` → **`AUTOTAGGING_RABBIT_RUNTIMEOUT`**

**写成 `AUTO_TAGGING_RABBIT_RUN_TIMEOUT` 不会报错，只是静默不生效。**

## Significance

这是「配了但不生效」的头号原因。代码里也有注释守着（`deploy/k8s/api.yaml`）：

```yaml
# 变量名规则：Spring 是「点换下划线、去掉连字符」，
# 即 tag.image-fetch.allowed-hosts 对应 TAG_IMAGEFETCH_ALLOWEDHOSTS_0；
# 写成 TAG_IMAGE_FETCH_... 不会绑定且静默失效。
- name: TAG_IMAGEFETCH_ALLOWEDHOSTS_0
```

### 验证绑定是否生效的手法

临时设一个会立刻见效的极小值（如 `run-timeout=5s`），看批次是否提前停。

⚠️ **只能用在隔离队列/临时环境**——生产 vhost 上试会让真实消息必然失败进死信。

### 已知踩坑实例

| 配置 | 正确写法 | 错误写法（静默失效） |
| --- | --- | --- |
| `auto-tagging.rabbit.run-timeout` | `AUTOTAGGING_RABBIT_RUNTIMEOUT` | `AUTO_TAGGING_RABBIT_RUN_TIMEOUT` |
| `tag.image-fetch.allowed-hosts[0]` | `TAG_IMAGEFETCH_ALLOWEDHOSTS_0` | `TAG_IMAGE_FETCH_ALLOWEDHOSTS_0` |
| `CALLBACK_AUTH_VALUE` / `CALLBACK_BRANDS` | 按同理映射 | 写错则回调鉴权/白名单静默失效 |
