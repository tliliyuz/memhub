> precheck → 场景（scene）→ 标签（label）→ 回调的四阶段链路，阶段状态是定位「0 标签」归属的第一分界线。

# Definition

一条打标消息的完整处理路径：

```
precheck() → 场景（scene）阶段 → 标签（label）阶段 → 回调
```

每一个阶段都可能「完成但什么都没产出」，因此**阶段状态**是排障的第一分界线。

# Significance

- 「打标完成但 0 标签」的最省时间判断：**这条消息发出过几次模型请求**。
  - **零请求** → 卡在 `precheck()`（主图缺失 / 主图域名不在白名单 / 图文冲突），见 [[静默失败]]。
  - 有请求但 0 标签 → 看场景概率（「箱包 0.58 / 香氛 0.42，都 < 0.8 → 0 标签」）或 [[闸门阈值]]。
- 阶段状态签名：`命中场景=[]，阶段状态=scene=completed,label=skipped` → **场景阶段零命中，标签阶段 skipped**，此时不要怀疑标签阶段。
- 一次运行的严格成败判据见 [[假成功与严格成功判据]]。

# Common topics

- **系统架构**：阶段划分与短路点（precheck / 场景零命中）。
- **数据流**：消息 → 阶段状态 → 回调载荷（`未配置回调地址` 日志带完整 payload）。
- **可观测性**：阶段状态比日志更可靠，`tag_task_evidence.evidence_gzip` 存每阶段 `elapsedMs`/token。
