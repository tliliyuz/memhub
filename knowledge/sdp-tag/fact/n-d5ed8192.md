> 租户上下文的归属从「按 userId 的 Redis 全局键」改为「按登录会话的 Token-Session」，是权限/多租户模型的核心裁决。

# Definition

租户上下文隔离描述**「当前请求属于哪个租户」这件事存在哪里、按什么维度区分**：

- **旧模型**：Redis 全局键 `global:dynamicTenant:<userId>`，TTL=-1，**按 userId 不按会话**。同一用户在不同会话/不同设备登录时共享同一租户上下文。
- **现模型**：写入登录会话 `Token-Session` 的 `dynamicTenant` 键，**按登录会话隔离**。旧键仅作为残留，在注销与重置时被清理。

实现落点为 [[TenantHelper]]。

# Significance

1. **排障路径变了**：租户串了不能再查 `global:dynamicTenant:*`；那条路径现在只会看到没人读的残留值。
2. **语义变了**：同一 userId 的两个会话可以有不同动态租户——这是「按会话」而非「按用户」的直接后果。
3. **这是「以代码为准」裁决的样板**：三批材料中两批（`[D]` `[Z]`，10-29~11-03）记录的是旧模型，只有贴近当时代码的 `[C]` 说了新模型；靠 `git grep` 行号 + `git log` 提交时间定案。见 [[时间线仲裁口径]]。
