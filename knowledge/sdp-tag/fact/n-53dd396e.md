> ACR 推送、Spring 配置绑定、代理、Git 共享工作区、长任务回收等 E1–E20 与 D2/D3/D5/D15/D16 的合集。

# 定义

开发环境与工具链陷阱是「与业务无关但反复消耗时间」的一类坑，共同特征是**错误信号指向错误方向**（网络、模型、并发），实际原因在工具链层。

# Schema：环境类（E1–E20 精选）

| # | 试了什么 | 结果 | 现在做法 |
| --- | --- | --- | --- |
| E1 | 宿主 `docker push` 到 ACR | 大层被 Docker Desktop 代理掐断 | pod relay + `crane push` |
| E2/E3 | 宿主 `crane` 直传 / `crane append` 叠层 | 48 KB/s；8 层 / 748 MB 死层 | `crane push` 整镜像 → 5 层 / 284.7 MB |
| E4 | 中文做 Spring `Map` 的 key | `ConfigurationPropertyName` 抹掉中文 → 5 条塌成 1 条 → **CrashLoopBackOff** | 改 `List<ReasonKind>` + 绑定回归测试 |
| E5 | 环境变量名按「连字符转下划线」猜 | `auto-tagging.rabbit.run-timeout` → **`AUTOTAGGING_RABBIT_RUNTIMEOUT`**（连字符被去掉），写错**静默不生效** | 记死规则 |
| E6 | key 写进 `config/application-private.yml` | 永远不生效（`spring.config.import` 优先级低于 `application.yml`） | key 走环境变量 |
| E7 | JVM 读 `HTTP_PROXY` | `proxySelector -> [DIRECT]`，返回 451 | `-Dhttps.proxyHost`，**必须在 `-jar` 之前**，每个 `-D` 单独引号 |
| E8 | Windows `curl` 下载图片 | `schannel: SEC_E_NO_CREDENTIALS` | Python `requests(trust_env=False)` |
| E10 | 临时脚本命名 `select.py` | 遮蔽标准库 | 不用 stdlib 名字 |
| E11 | 19 位主键走 float/Excel | `...690` → `...688`，报「商品不存在」 | 保持文本列 |
| E12 | 假设「同配置重跑一致」 | 不可复现 | 先跑噪声基线 |
| E13 | 本机直连图片域名 | Clash fake-IP → `198.18.0.31` 被判非法 | `-Dtag.image-fetch.allowed-networks=198.18.0.0/15`（只本机） |
| E14 | 用 API Key 调 `requeue-failed` | `@SaCheckPermission` 没有 `@ApiKeyAccess` | 「有权限码 ≠ 能用 API Key 调」 |
| E16 | Git Bash 传 `/applesay` 给 Java | 被改写成 `C:/Program Files/Git/applesay` → `VhostNameInvalid` | `MSYS_NO_PATHCONV=1 MSYS2_ARG_CONV_EXCL="*"` |
| E18 | 两个真实 DB 的 Spring 测试同 JVM | `... found 2` | 一个类一个类地跑 |
| E19 | Mockito stub class（非 interface） | `when(mock)...thenThrow()` **静默无效** | `doThrow(...).when(mock)...` |
| E20 | Git Bash 里跑 JVM | 本地 DNS 返回 fake-IP | `-Djdk.net.hosts.file` + DoH 公网 IP |

# Schema：Git 协作类（D2/D3/D5/D15）

| 坑 | 后果 | 应对 |
| --- | --- | --- |
| `git update-ref` 移动被别的 worktree 占着的分支（D2） | 制造「已暂存的、内容恰好是回退」的假改动，谁顺手 `git commit` 就把同步整个回退 | 识别：HEAD 是新提交但 index/文件停在旧提交，文件 mtime 恰是别人 fast-forward 的那一刻 |
| `.gitignore` 只 `git rm --cached` 不加规则（D3） | 后续 `git add -A` 把 5 个文件原样加回 | 已补 `.tmp_*`、`.tmp-build/`、`~$*`；**共享仓库里 `git add -A` 会静默暂存别人的文件**，只暂存你明确拥有的路径 |
| 提交「工作区里的未提交改动」（D4） | `20 / 85,36` 这类算不出来的数、`.eslintrc-auto-import.json` 丢 4 个 `El*` 项而 `src` 有 50 处依赖 | 生成文件报告状态前先 `git checkout --` |
| 全量取 theirs 合并（D5） | 把无关本地功能（租户会话隔离）一起回滚 | 逐文件确认后重做 |
| 共享仓库/worktree 分支被动（D15） | 提交只存在于旧分支、worktree 被删、xlsx 被占、`dev` 在脚下移动 | 合并前 `git status -sb` + `git log --oneline -1`；用 `git checkout <commit> -- <paths>`；从当前 `dev` 建 worktree |

# 最重要的一条

⚠️ **抽 logic 到 [[打标引擎（TagEngine）]] 后，远端仍在改 `TagLabServiceImpl`，Git 会把远端编辑「干净地」合进死代码**（重复踩过两次）。每次合并后都必须 diff 引擎与远端 lab 里的 `stagesOf`、`hitDimensions` 移除、`requestTokenLimit`、`batchStateOf`。
