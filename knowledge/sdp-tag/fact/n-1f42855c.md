> 打标流程从 scene → dimension → label 收敛为 scene → label，是演进而非矛盾；引用历史数字必须声明当时是几阶段。

# Definition

打标流程的阶段序列：

- **旧（三阶段）**：`scene → dimension → label`
- **现（两阶段）**：`scene → label`，`dimension` 阶段已退化/移除

权威实现为 [[TagWorkflowService]]（`TagWorkflowService.java:60/78`）。

# Significance

1. **历史数字的可比性**：老 Spec、老导出数据、老评测基线**都还是三阶段的**。引用历史数字时必须说明当时是几阶段，否则会把「阶段变了」误读成「效果变了」。
2. **收益未被测量**：取消维度阶段的收益**从未被量化**——Spec §6 自己写着没有 100 件对比，评估方案未执行（C13）。因此「这个改动值不值」目前无法回答（E9）。
3. **定义的作用点变了**：`dimension` 阶段退化后，维度定义主要通过判分侧与打标侧的提示词起作用，见 [[维度定义的生命周期]]。

# 冲突与裁决

**A2：阶段到底几个？**

| 说法 | 来源 | 时间 |
| --- | --- | --- |
| 只有 `scene → label` 两阶段 | `[C]` `[D]` | 11-05 起 |
| 3 stages: scene / dimension / label | `[D]` 部分 | 11-02 ~ 04 |
| 「dimension stage vestigial/legacy」 | `[Z]` | 10-30 |

**裁决：不是矛盾，是演进。** 代码可验证。`[Z]` 的「vestigial」描述与 `[C]` `[D]` 的「两阶段」是同一事实的早期/晚期表述。

# 与合批的关系

阶段内的合批/标签合并行为受 [[TagLabProperties]] 的 `labelMergeEnabled`（默认 `false`）影响；该开关是**活配置**（A3 裁决）。合批的 R4/R7 100 件扩展验证未做（C6，只跑了 10 件 × 四臂）。
