# 评测框架与续跑一致性

## Definition

[[lab-accuracy-tool]] 的实现框架：**三评 + 仲裁**的离线判分流程，以及保证多次运行可续跑的约束。

## Significance

评测的结论必须**可复现**。任何影响提示词哈希的输入（rubric、模型名）变了，结果就不可比，框架会主动拒绝续跑——这是设计意图，不是 bug。

## 流程

| 环节 | 默认模型 |
| --- | --- |
| 判分 1 | `qwen3.8-flash` |
| 判分 2 | `gpt-6.1-sol` |
| 判分 3 | `grok-4.7` |
| 仲裁 | 由上述分歧触发 |
| 默认（单评）模型 | `deepseek-v4.1-flash-1017`（`judge.py:23`） |
| 默认 base-url | `https://applesay-api-hup.applesay.cn/v1`（`judge.py:24`） |

## 续跑一致性约束

- ⚠️ **`--rubric` 会进提示词哈希，续跑必须一致**，否则会拒绝续跑
- ⚠️ **部分/中止的 score run 会污染续跑** → 重跑前删 `chunks.jsonl` 和 `scoring-state.json`
- ⚠️ **`--reuse-baseline` 按输入指纹匹配**，指纹变了会「禁止复用」

## 跑批前置条件

- `mvn test` **默认被跳过**（`<skipTests>true</skipTests>`）→ 必须 `-DskipTests=false`
- 临时 SpringBootTest 要加 `@Tag("dev")`，否则 surefire 跑 0 个测试
- 数据库须先 apply SQL（见 [[db-schema-change-management]]），且测试走 [[isolated-test-db-guard]]
