# 图谱归属与协作边界

## 定义

一条协作规矩 `[Z]`：

> 用户负责**打标部分**（lab、prompts、阈值、judge 调用）。**知识图谱内容属于另一个团队**——场景/维度定义、标签备注、标签关系。
>
> 所以：打标问题溯源到图谱内容时，**报告证据 + 建议措辞，交给图谱团队**，不要直接改图谱表。

## 意义

- 这是 [[知识图谱]] 无 `tenant_id`、每行业一套的结构性后果：内容变更影响所有租户，必须由单一 owner 决定。
- 决定了问题定责路径：模型/judge 问题归 [[打标侧]]，内容问题归 [[图谱团队]]。

## 边界清单

| 资产 | Owner |
| --- | --- |
| [[场景]] / [[维度]] 定义、标签备注（remark）、标签关系 | [[图谱团队]] |
| [[打标实验台]]、prompts、[[阈值体系]]、judge 调用 | [[打标侧]] |
| 评测口径（[[准确率口径]]、[[三评架构]]） | [[打标侧]]（基于 [[评测工具]]） |

## 易误解

- 直接改图谱表会绕过 owner，导致实验对照失效（例如维度定义被清空却不自知）。
- 打标侧「发现 48 个 0 标签维度」的处置是报给图谱团队，而非自行补标签。
