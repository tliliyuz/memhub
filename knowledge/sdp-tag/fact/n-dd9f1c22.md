> 维度定义同时进打标侧与判分侧；第三 cohort 实为「定义清空」而非「定义精简」，该方向从未被真正测量。

# Definition

维度定义（`dimension_definition`）是每个维度下给模型/judge 的自然语言说明。它同时进入：

- **打标侧**——模型生成标签时的提示词上下文
- **判分侧**——judge 判断标签是否正确的依据

因此定义类改动测的是「**端到端自洽**」，不是「定义让模型更准」。

# 关键事实与时间线

| 时间 | 事件 |
| --- | --- |
| 2026-10-23 | 改过 1 个定义、开了 `attr5` |
| 2026-10-26 09:21 | 重写 **140 个**维度定义 |
| 第三 cohort | **定义清空**：141 个 `dimension_definition` 全为 NULL（查 DB 确认） |

# 冲突与裁决（A7）

| 说法 | 来源 |
| --- | --- |
| 「精简版维度定义」效果 | `[D]` 按当时理解 |
| **实际跑的是定义被清空**（141 个 `dimension_definition` 全 NULL） | `[Z]` 查 DB 确认 |

**裁决：`[Z]` 对。** 第三个 cohort 必须叫「**定义清空**」。

**影响面很大**：它意味着「定义精简」这个方向**从来没被真正测量过**，后来基于它做的推论都要打折扣。

# Significance

1. **解释力被误归因**：把「定义清空」的效果当成「定义精简」的效果，是整个评估链条上最贵的一处误读。
2. **改动类型决定对照强度**：**阈值类改动**只影响打标侧，对照更干净；**定义类改动**两侧都动，只能测自洽性。
3. **历史对比必须显式对齐**：定义会变、快照会冻结，跨时间对比前必须对齐（见 [[评测噪声与可比性]]、历史对比对齐章节）。

# 已失效结论

- **B10**：「一个标签只挂一个维度是代码保证的」——**一直没保证**；这是契约要求，代码不保证。

# 未决与缺口

- **C10**：`graph_label` 没有 `definition` 列（实际列名是 `remark`）——引用「定义」时必须用对列。
- **C13 / E9**：取消维度阶段的收益未测（Spec §6 自述没有 100 件对比），因此「定义/阶段」类改动的价值判断缺数据。
