> HTTP 200 ≠ 成功；「假成功」= 返回 200 且写了库但标签未过严格判定（形式成功）；严格成功需 failedBatchCount==0、label 阶段非 failed/skipped、标签数>0 三条同时成立。

# 假成功与严格成功判据

## Definition

把「看起来成功」与「真的成功」区分开的判据体系。

**假成功**：对方业务失败也返回 HTTP 200；我们只看 2xx 就认为成功。

**严格成功判据**（三者**同时**成立）：

```
failedBatchCount == 0
且 label 阶段不是 failed|skipped
且 标签数 > 0
```

## 字面意思 vs 团队实义

- **字面意思**：看起来成功了（返回了 200、数据也进库了）。
- **团队实际含义**：打标任务返回 200 且已写入数据库，但**实际标签未经过严格判定**，属于「形式上成功、实质上不合格」。
- **易混淆点**：与真正的「严格成功」相对。**判据在返回码之外** —— 还要看标签是否通过全部闸口。

## 两层判据

| 层 | 判据 | 说明 |
|---|---|---|
| 形式成功（= 假成功） | HTTP 200 + 数据已写库 | 只证明链路跑通，不证明产物合格 |
| 严格成功 | `failedBatchCount == 0` **且** label 阶段状态非 failed/skipped **且** 标签数 > 0 | 三条同时成立才算一次运行成功 |

因此「200 + 写库」只是形式成功的**必要条件**，不是成功判据本身。任何只看 HTTP 码或只查「有没有行落库」的验收，都会把假成功计入成功率。

# Significance

- 不能只看 HTTP 200：对应日志是 `回调业务失败（HTTP 200），url=…，响应=…`（带响应体，最有用）。
- 判据的每一行都对应一种假成功：
  - `failedBatchCount == 0` —— 批次部分失败但整体 200。
  - label 阶段非 `failed|skipped` —— 场景零命中或[[闸门阈值]]导致的空跑。
  - 标签数 > 0 —— 「打标完成但没有标签」会**回调空结果**。
- 同类脏指标：`passedDims` 恒空、coverage 用 `>=` 而链路用 `>`（边界值判反），见 [[评测口径一致性]]。

## 为什么会假成功（常见来源）

- [[对方-v2-回写系统]] —— 业务失败仍返回 HTTP 200，是「假成功」最主要的外部来源。
- 闸门高于阈值导致标签永不产出但流程不报错，见 [[闸门阈值]] / [[闸门取-min-不变式]]。
- 阶段状态为 skipped 但任务整体标 completed，见 [[状态与归因语义]]（completed ≠ 有输出）。

## 排障用法

用 [[打标四阶段链路]] 的阶段状态反查假成功发生在哪一段：precheck → [[场景]] → [[标签]] → 回调。阶段状态是定位「0 标签」归属的第一分界线。
