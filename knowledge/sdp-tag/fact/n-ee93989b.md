> 2026-10-26 删除独立维度判断阶段，流程改为 scene → label，用 token ×2 与准确率 −1.2pp 换取 565 个被门挡掉的标签。

# 定义

2026-10-26（`69f77f1`）删除独立的维度判断阶段，打标流程从 `scene → dim → label` 变为 **`scene → label`** 两阶段。

# 动机

维度门既可能**错挡**（H 组丢了 77 个维度命中 = −90 个正确标签），又可能在**过滤噪声**（补全标签只有 44~61% 准确）。团队自己也标注了这个张力。

# 代价（硬数据）

| 指标 | 变化 |
| --- | --- |
| support | 2,514 → **2,968（+454，+18.1%）** |
| 准确率 | 86.8% → **85.6%**（CI −2.12 ~ −0.35pp，不含零） |
| 新标签 | 605 个（support 472 / contradict 25 / unknown 108） |
| 其中来自被门挡掉的维度 | **565 个** |
| label 题数 | **+88.5%** |
| tokens | 13.99M → **28.02M（×2）** |
| 每多一个正确标签的代价 | **约 30.9k token** |
| 墙钟 | 5.14 → 19.47 s |

- **新错误集中**：服装袖型（9/9 contradict）、服装花纹图案（9/36）。
- **准确率下降由 unknown 驱动**，decisive 准确率持平（94.7% / 94.9%）。

# 收益从未被正式测量

⚠️ `project-drop-dimension-stage-eval.md` 明确说「什么也没跑，用户没回答」，Spec §6 也说没有 100 件对比。**上面的数字是一次配对跑的副产品，不是专门设计的实验。**

这是 [[架构决策先落地后补测量的流程问题]] 的典型实例。
