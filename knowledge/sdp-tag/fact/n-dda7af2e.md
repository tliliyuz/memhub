> 本项目的「准确率」始终是 judge 估计而非真值；三个可接受方案均不含人工标注，用户明确禁止人工标注作为门控。

# Definition

这个项目**从来没有人工金标准**。所有被称为「准确率」的数字，其含义始终是「**judge 估计**」，不是真值。

`[Z]` 记录的三个可接受方案，**都不含人工标注**：

| 方案 | 做法 | 成本 |
| --- | --- | --- |
| **A（推荐）** | 三模型共识，只判 **1,240 个翻转对** | ~20~30 min |
| **B** | 全量双判 + 混淆矩阵 + kappa | ~5 h，一次性方法验证 |
| **C** | 不裁决，报 strict / decisive / unknown 三元组 | 0 |

**用户明确要求「计划里不要出现需要人工标注作为门控步骤」。**

# Significance

1. **口径即真值定义**：因为缺真值，判分口径（strict / inference）事实上定义了「准确率」这个词的含义。见 [[rubric 判分口径]]。
2. **方案 B 的价值**：kappa 是唯一能给出「judge 之间一致性」的量化指标，且是一次性方法验证，不构成日常门控——这是绕开人工标注仍能获得可信度的路径。
3. **所有绝对分数都是相对的**：68.2% 与 88.0% 之间的 19.8 pp 不是「模型变准了」，而是「标准变了」。

# 关联缺口
