> ingress 60s 与 web nginx 300s 是两个独立天花板，短的赢，必须两层一起抬；判别信号是应用日志无请求 + nginx 499。

# Definition

端到端 504 由**两个独立的超时天花板**决定（`[Z]`）：

| 层 | 默认 | 在哪改 |
| --- | --- | --- |
| [[ingress-nginx]] `proxy-read-timeout` | **60s** | `deploy/k8s/ingress.yaml` 注解（已改 600） |
| [[sdp-tag-web]] 容器内 nginx `proxy_read_timeout` | **300s**（已改 600） | `deploy/web/nginx.conf`，**改了要重建 web 镜像** |

# Significance

- **短的赢**：只抬一层等于没抬，**必须两层一起抬**。
- **判别方法**：应用日志里**根本没有这次请求** + web 的 nginx 记 **499**（客户端断开）→ 请求在 ingress 就被掐断，与业务慢无关。
- 与「慢」的区别：`run-timeout` 只在批次之间检查，单次模型调用可以拖过所有超时（见 [[租约与重试上限]] 与 [[打标四阶段链路]]）。
