> 多条路径「失败但不报错」——HTTP 200 假成功、precheck 失败只写 status 后 continue、闸门高于阈值导致标签永不产出、变量名写错静默失效；是本系统最跨领域、最反复出现的失败模式。

# 定义

静默失败（silent failure）指系统在**没有产生任何告警**的情况下丢数据或降级。它有两副面孔，本页同时收录：

1. **假成功型**：调用方看到的是成功语义（HTTP 200 / ACK / `status=success` / 空数组），实际结果缺失或不完整。
2. **无信号失败型**：没有异常、没有 ERROR 日志、没有指标，只有结果悄悄地不对（如 `precheck()` 失败后只写 `status=failed` 就 `continue`）。

本页讲**跨领域的失败模式本身**；具体机制见 [[消息可靠性与死信（DLX）]]、[[幂等键与缓存指纹]]、[[对方 V2 回写系统]]、[[打标四阶段链路]]；缺口状态见 [[已知未修缺口清单]]。

# 重要性

它是本文档中**最跨领域**的问题，横跨联调、消息、评测、运维四层。大多数「数据对不上」的排查都终止于某个静默失败点。

它同时也是排障手册里**最反复出现的一类陷阱**——因为它让人**把「没有信号」误读为「没有问题」**，从而跳过「先证明是缺陷」这一步（见 [[排障范式]]）。

> **有告警不等于修好了**：修了静默路径只意味着现象可见，不代表功能可用。见下文「分层原则」。

# 表现形式

## 一、假成功型（成功语义掩盖缺失）

| 表现 | 机制 | 出处 |
| --- | --- | --- |
| 假成功 | 对方业务失败仍返回 HTTP 200（body `code=400`），我方记成功并 ACK | C6 |
| 空 `tags` 也 ACK | `tags 为空 \| code 200 \| 无记录`，算「成功回调」但不落库 | C6 |
| 从未调用模型 | `tags:[]` 的那条日志 1 秒就 log-only 回调，`grep -c "LLM 判断请求"` 两小时为 0；空结果产生在 judge 之前（没配 judge / `resolveJudge` 返回 null / 场景零候选 / 主图被拦 / 输入为空） | C7 |
| 401「跑通了」 | 401 抛 `AmqpRejectAndDontRequeueException`，消息 reject 且不重回队列 | C5 |
| 拒绝即丢 | 未配 DLX，broker 直接丢弃，日志仍打「转死信」 | B5 / G1 |
| 部分结果当成功 | `run-timeout` 到点停止派发后照常回调，`assertStagesSucceeded` 不拦部分失败 | B9 / G2 / G3 |
| 毒消息打死容器 | 缺 `productName` → 重试耗尽 → 停消费者，后续 1,960 条堵死 | D12 |
| 静默丢维度 | 标签多维度回写只取第一个 | G6 |
| 静默跳过 | 幂等键不含品牌，两品牌 SPU 重叠时后到者被跳过 | G4 |
| 坏数据进分母 | 只判 HTTP 200 当采集成功 → 7 件 0 标签坏数据抬高准确率 | F1 |

## 二、静默路径型（失败但无任何信号）

| 路径 | 表现 |
| --- | --- |
| `precheck()` 失败 | 只写 `status=failed` 然后 `continue`，**不记日志、不抛异常**（[[打标四阶段链路]]） |
| 场景零命中 / [[闸门阈值]] 高于正式阈值 | 那部分标签**永远不产出且不报错** |
| 环境变量名写错（`TAG_IMAGE_FETCH_...` vs `TAG_IMAGEFETCH_...`） | 配置**静默失效**，见 [[主图抓取放行模型]] |
| 无路由键投递到默认交换机 | 消息**静默丢弃**，日志里什么都没有（[[aliyun-serverless-amqp]]） |
| `auth_key_ref` 建行冻结 | 永远 `config_blocked`，改配置不自愈（[[回调投递状态机]]） |
| 老导出缺 `taggingPrompts` | 样本被整件跳过，静默减少（[[评测口径一致性]]） |
| SnailJob 缺 `openapi.*` | 无限重试但**没有堆栈**（[[snailjob]]） |
| `passedDims` 恒空 | 39 个漏打全部记成 `dimension_miss`（脏指标） |

# 对抗手段

1. **成功判据显式化**：采集侧要求 `failedBatchCount == 0` 且 label 阶段非 `failed|skipped` 且标签数 > 0（F1）；回写侧要求 HTTP 2xx 且 `body.code ∈ {0, 200}`（C6）。参见 [[假成功与严格成功判据]]。
2. **机制化解法**：配置 DLX、拦部分失败、graceful shutdown（G1/G2/G7）。
3. **功能探针替代指标**：不信任 `consumers`，发几条测试消息看是否还在队列（C9）。
4. **日志反证**：`grep -c "LLM 判断请求"` 这类「应该发生的事有没有发生」的计数，比状态字段可靠（C7）。相关手段汇总见 [[可观测性探针]]。

## 分层原则（验收口径）

> 「**我只让它不再静默，没让它能下载图片**」——有告警 ≠ 修好了。

修复一个静默失败要分两层验收：**现象可观测**（日志/指标出现）与**功能正确**（结果符合预期），二者不可互相替代。
