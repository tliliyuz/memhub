> C（Codex/代码侧）、D（部署与后续迭代会话）、Z（lab 实验与判分记录）三批来源各自只在部分主题上权威，必须合并使用而非择一。

# 定义

三批材料来自不同时间、不同工具，覆盖的主题范围不同。**没有任何一批能单独支撑全部主题**，因此知识库必须合并三批，而不是选其中一批作为唯一事实源。

# 分工表

| 主题 | C | D | Z |
| --- | --- | --- | --- |
| 10-19~10-25 lab 实验（A~H 组） | 少 | 几乎没有 | **权威** |
| 判分口径与三评架构 | 少 | 部分 | **权威** |
| 10-26~10-29 部署与 MQ 打通 | 部分 | **权威** | 部分 |
| 11-03~11-06 MQ 幂等/回调/分维阈值 | 少 | **权威** | 无 |
| 配置与凭据位置 | 只有路径 | **权威**（含状态） | 部分 |
| 用户偏好（文档风格等） | 无 | 无 | **权威** |

# Significance

- 决定了「同一个问题该去哪个来源查」：例如 [[商品打标实验台]] 的实验记录只能信 Z，[[MQ 消费链路]] 的幂等与回调只能信 D。
- 与 [[仲裁口径]] 配套：分工表说明「谁权威」，仲裁规则说明「权威冲突时怎么裁」。
- 解释了为什么会出现「同一结论在不同来源中相反」——往往只是各自只覆盖了某件事的一个阶段（如 [[阶段演进]]）。

# 范围示例

- Z 权威区：[[商品打标实验台]] 的 A/B/C 组实验、[[判分口径]]、[[补全路径]] 的实测数据。
- D 权威区：[[TKE 集群]] 部署、[[MQ 消费链路]] 后续迭代、[[分维阈值机制]]、配置与凭据状态。
- C 权威区：贴近当前代码的事实，在 [[仲裁口径]] 规则 1 中优先级最高。
