> 租约 3 分钟 + 每次重领 attempt_count+1，超 4 次终态 failed 且永不回调——把延迟变成永久失败。

# Definition

任务执行权的租约机制：任务被领取后获得 3 分钟租约；租约过期后可被重新领取，且**每次重领 `attempt_count + 1`**；超过 **4** 次进入终态 `failed`，**永远不会再有回调**。

# Significance

> **积压本身不可怕，租约过期计次才致命。**

- 它**把延迟变成永久失败**：线程池满 → 拿不到执行 → 租约过期被重领 → 计次烧穿 → 终态 failed。队列积压原本只是慢，最终变成数据缺失。
- 失败信号：日志「任务执行次数已达上限，过期租约不再重试」；查 [[tag_task]] 的 `attempt_count` 与 `lease_expire_time`。
- 与 [[静默失败]] 的组合效应：任务终态 failed 不发起回调，下游看到的是「打标成功但没回调」，容易误判成权限/URL 问题。
