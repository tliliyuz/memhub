> 用 16 个业务字段字典序拼装 + 长度前缀 + 空白与 imageUrls 归一生成幂等摘要，不再证明字节一致。

# 定义

幂等判定不再依赖原始报文字节，而是对**解析后的业务内容**做规范化摘要：

- 只取 16 个参与打标的业务字段
- `TreeMap` 字典序拼装
- 值长度前缀（防字段拼接歧义）
- 空白归一 + `imageUrls` 三种写法归一
- `messageId / trackId / tenantId` **不入摘要**

# 意义

对方只是把报文包了一层 `productInfo`，字节摘要就全变了 → **100% 出现 `EVENT_CONFLICT`**。规范化摘要容忍报文多包一层。

# 关键约定

- `message_digest` 语义不变（恒为首次报文摘要），作为**审计稳定键**。

# 代价

摘要不再能证明「字节完全一致」，只能证明「参与打标的业务内容一致」——这是有意选择。
