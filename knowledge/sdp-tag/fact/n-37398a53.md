> 打标系统术语语义澄清清单——逐词给出「团队实际指什么 / 容易误解在哪 / 怎么验证」，揭示同一说法对应的多种实现含义。

# 01 术语实义

## 文档性质

术语语义 / 工程共识文档（非需求、非架构设计）。对打标系统里团队常用词逐条给出三段式定义：**团队实际指什么** / **容易误解在哪** / **怎么验证**（给出代码位置或实测数据）。

核心价值：揭示**同一个说法对应多个不同的实现含义**——「门」有三种、「judge」有两种、「租户」有两套编号、「指纹」至少五个哈希。

## 一张总表：说法 vs 实际

| 团队说法 | 代码/数据里实际是 | 差异点 |
| --- | --- | --- |
| 行业 | `scene` | 7 个 scene，**没有「家居」** |
| 场景 / 行业 | 同一个东西 | 2026-10-27 起 UI 叫「行业」，代码全 scene |
| 维度阶段 | **2026-10-26 起已删除** | 只剩 `scene → label` |
| 多维度标签 | 契约禁止，数据恰好单维 | 无代码强制，只有导出接口加校验 |
| 直标 | `tag_product_label.direct` | 团队无明确定义 |
| 矛盾 | reason 枚举「明确不符」 | 是依据类型，不是分数 |
| unknown | 准确率分母里的「证据不足」 | 不打进标签表 |
| 门 / gated | 两个完全不同的东西 | 见 [[门控]] |
| 回刷 | 无此词 | 只有回写 / 重放 / 强制重跑 |
| 指纹 | 至少 4 个不同哈希 | 不区分是最大误解源 |
