> 回调 URL 与 header 名放 sys_config（运营可改、即时生效），key 只留引用名，真值挂 Secret 环境变量。

# 定义

回调配置按敏感度分层存放：

| 内容 | 放哪 | 为什么 |
| --- | --- | --- |
| 回调 URL、header 名 | [[sys_config 配置中心]]（Redis 缓存，改完即时生效） | 运营可改 |
| **key 值** | [[Secret]] | 见下 |

# 为什么 key 不能进 sys_config

> 「『参数设置』页面对有权限的人是**明文可见**的，而且会进 DB 备份；DB 的暴露面比 Secret 大得多——**今天我就是拿一个 root 账号直接把 key 读出来的**。」

# 折中方案

`sys_config` 只存**引用名**（`tag.callback.auth-ref = zara-key`），真值仍由 Secret 挂成环境变量。

# 容易踩的缓存坑

`sys_config` 按租户 Redis hash 缓存（`<tenantId>:sys_config`）：**直接在 MySQL 里改 `sys_config` 不生效，必须先把那个字段从 hash 里 `HDEL`**。
