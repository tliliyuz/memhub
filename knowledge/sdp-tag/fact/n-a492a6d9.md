> 三批材料冲突时一律「以代码为准 + git commit 定时间」，并显式标注结论失效点，是引用其他结论的前置校验。

# Definition

时间线仲裁口径是本知识库的**冲突裁决规则集**：

1. **以代码为准**：会话/文档说法与源码冲突时，源码胜出。代码断言须用 `git grep` / 行号核验。
2. **用 git commit 定时间**：判定「某个结论什么时候失效」，以提交时间与分支状态（是否在 dev）为准。
3. **显式标注失效点**：每条被推翻的结论都要写「何时失效 + 现在应该怎么说」。
4. **区分「矛盾」与「不同阶段」**：同一件事在不同阶段的两种描述不是冲突，不能只保留一个。

# Significance

它是**引用 01–05 任何结论之前的强制前置校验**：几乎所有 A/B 类条目都在约束「某个结论现在还能不能这么说」。

`# 已失效结论` 列表（B 类 16 条）就是这条规则的产出物，散布在各实体/概念页中。凡含失效列表的页面，引用前应先读该列表。

# 应用样例

## 样例 1：以代码为准（A1 / A3）

- A1 租户上下文：`[D]` `[Z]` 都说按 userId，`[C]` 说按会话。`git grep` 核到 `TenantHelper.java:37/150/196` + `git log` 到 `0ed738d`（2026-11-04），结论为会话隔离。
- A3 `label-merge-*`：11-05 **只读快照**判为死配置，11-04 **实现记录**判为活开关。代码里 `TagLabProperties.labelMergeEnabled` 真被使用 → 活开关。
  **教训**：只读快照会把「当前链路未触发」误判为「死配置」，必须回到调用点。

## 样例 2：同一件事的不同阶段（A4）

ACR 慢：`[D]` 记代理链路 `broken pipe`（`192.168.65.1:3128`），`[Z]` 测实例侧 0.2 MB/s 上限。**两者都对，指不同现象，都保留**——合并结论是「宿主直推不可用，pod 中转是正确方案」。

## 样例 3：更精确的一方胜出（A5）

`kubectl exec`/`cp`：`[D]` 把两者归为同类超时；`[Z]` 区分出 `exec` 重试后可收敛、`cp` 不可收敛。裁决取 `[Z]`，因为它在**同一现象内做出了更细的区分**。

## 样例 4：不是矛盾是演进（A2）

三阶段 vs 两阶段 = 阶段演进，不是谁记错了；但要求「引用历史数字必须说明当时是几阶段」。
