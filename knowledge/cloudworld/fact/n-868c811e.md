> 说明账号级默认会话资产记录存在时会短路会话资产解析链、静默覆盖请求头与交互表单，并给出排障判定与恢复表单流程。

# 摘要

本文解释「新会话不弹 team/agent/task 资产选择表单」这一现象的成因：当账号下存在 `user-session-default` 记录时，服务端 v3.3 的会话初始化分支会直接采用账号默认，并**完全跳过**请求头（`x-team-id` / `x-agent-id` / `x-task-id`）与交互表单这两档。这是有意设计的优先级，不是表单故障，也不是配置泄漏。

# 核心结论

- 解析顺序：`账号默认（user-session-default） > 请求头预设 > 交互表单`，短路式生效——命中第一档即跳过后续所有档，**包括请求头**。
- 「在 header 里指定了 agent 却没用」属于预期行为，而非 bug。
- 没有单独开关可以关闭「账号默认」这一档；服务端只有 `sessionInit.enabled` 这一级总闸（默认 `false`），关掉它等于停掉整条会话初始化链路。
- 恢复表单的唯一手段是删除账号级记录：`cloud-world asset unbind`，再用 `cloud-world asset default` 确认返回「未设置默认资产」。

# 解析顺序（服务端 v3.3 分支）

```
账号默认（user-session-default） > 请求头预设 > 交互表单
```

| 档位 | 载体 | 命中后行为 |
| --- | --- | --- |
| 第一档 | [[账号级默认会话资产记录]] | 直接采用，后两档完全跳过（含请求头） |
| 第二档 | [[请求头预设]] | 仅在无账号默认时生效 |
| 第三档 | [[交互式资产选择表单]] | 兜底；非交互模式下不可用 |

详见 [[资产解析优先级链]]，实现位置为 [[会话初始化服务]]。

# 症状与判定

| 症状 | 判定 |
| --- | --- |
| 新会话不出现 team/agent/task 选择 | 账号默认存在（预期行为） |
| 指定 `x-agent-id` 无效 | 账号默认优先级更高（预期行为） |
| 想恢复表单 | 删除账号级记录：`cloud-world asset unbind` |

判定方法论见 [[预期行为 vs bug 判定]]；恢复步骤见 [[账号默认资产恢复流程]]。

# 有没有开关能关掉这一档

**没有单独开关。** 服务端只有 [[会话初始化]] 的 `sessionInit.enabled` 总闸（默认 `false`）：关掉它等于整条会话初始化都不执行，那不是「恢复表单」，而是把机制整个停掉。所以「搜遍配置找不到开关」是对的，但结论不是「关不掉」，而是**删除该账号级记录**。

# 设计动因

`claude -p`（非交互模式）无法渲染确认表单。把选择固化到账号级，是让非交互会话也能拿到确定的 team/agent/task 的唯一办法；反过来，一旦固化，交互会话也就不会再问。见 [[非交互会话资产固化]]。

# 容易搞错的一点

`user-session-default/set` 由服务端校验成员关系、agent 归属与可见性，**客户端不做本地猜测**。写失败时不要在前端猜原因，原样透传服务端错误。见 [[服务端权威校验]] 与 [[资产服务]]。
