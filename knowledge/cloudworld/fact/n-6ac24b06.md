# 凭据边界（06）

## 摘要

本文档确立一条核心设计结论：**凭据是功能硬门槛，不是界面门槛**。`user_key` 只存放在系统凭据库（Windows Credential Manager，service `cloud-world`）中，**缺失凭据时连接请求会被拒绝，且不产生任何文件**；而界面能否进入主视图与是否通过鉴权是两件相互独立的事——进得去不代表过了鉴权，只有点「连接」才会真正校验。

在此基础上，文档给出四个层面的规定：

1. **存放位置**：密钥只进凭据库，配置文件 `%APPDATA%\cloud-world\config.toml` 不含任何密钥。
2. **多 profile**：通过凭据库 account 前缀 `<profile>:` 实现天然隔离，无需额外作用域机制。
3. **登录门禁**：`App.tsx` 以 `!env.config_exists || env.profiles.length === 0 || prefill` 判定是否进入 LoginView；`prefill` 用于「有 profile 但 `has_user_key === false`」时只补 key、不重建 profile。
4. **密钥卫生**：key 不上日志、不进命令行、不进仓库、不进普通配置文件；内存用后 `zeroize()`，临时文件即用即删。

## 关键结论表

| 结论 | 依据 |
| --- | --- |
| 缺凭据 → 连接被拒绝且不写文件 | 凭据是功能硬门槛 |
| 进得去主视图 ≠ 过了鉴权 | 「直接进来了」= 本机早已登录过 |
| key 不进配置文件 | 配置文件是明文，易进备份 / git / 截图 |
| key 不进命令行 | Windows 上进程命令行对其他用户可见（`Get-CimInstance Win32_Process`） |
| 多 profile 不需额外作用域 | account 前缀 `<profile>:` 天然隔离 |
