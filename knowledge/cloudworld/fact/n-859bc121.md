> memhub 面板 API 并存三种互不兼容的响应形状，必须按端点分别解析，禁止统一封装。

# Definition

[[memhub 云端面板 API]] 的响应体存在三种互相不兼容的形状，同一套 API 内并存：

| 形状 | 端点 | 特征 |
| --- | --- | --- |
| 裸 JSON | [[meta-instances 端点]] | 无外壳，无鉴权 |
| 信封 | [[meta-auth-verify 端点]]、[[meta-action 端点族]] | `{code, message, request_id, data}`，`data` 内层形状不定 |
| 裸扁平 JSON | [[auth-user-key-login 端点]] | 不套信封，字段直接在顶层 |

# Significance

- **禁止统一封装**：任何「一个解析器处理所有端点」的设计都会在某个端点上静默出错——要么把信封当业务字段，要么把业务字段当信封字段。`crates/cloud-api/src/lib.rs` 顶层注释明确规定三种形状不得统一处理（见 [[cloud-api-crate]]）。
- **解析分支与鉴权分支耦合**：形状不同往往意味着鉴权语义也不同，必须一起设计，见 [[无效凭据语义分裂]]。
- **错误判读的前置条件**：先确定形状，才能正确读懂 `code`/`valid`/HTTP 状态码，见 [[错误码判定表]]。

# Common Topics

- 系统架构：接口层需要为每种形状保留独立适配器，而非单一 DTO。
- 数据流：响应解析 → 形状判别 → 业务分支（`valid` / `code` / `data`）。
- 模块边界：协议细节封在 [[cloud-api-crate]] 内部，向上暴露领域对象。
