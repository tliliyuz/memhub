> 交付验收须区分「已做」与「未做」，未做项单列成表才算完整证据；缺 lint 等隐性缺口必须显式声明。

# 验收证据分层

## 定义

验收证据要分层：交付报告里的「做完了」不构成证据，**没做什么**才是。完整证据由两层构成——可复核的通过项，以及**原样保留的未做项清单（Not-done list）**。

## 意义

- 只报通过项会制造「已全面验证」的错觉。典型例子：`clippy` 缺失时报告「构建无警告」，极易被读成「代码质量已检查」；因此必须显式声明 **lint 没跑**。
- 未做项本身是后续工作的输入：NSIS 未打包 → 部署模型未验证；只在 Windows 实测 → 跨平台路径未验证。
- 与 [[实测口径]] 互为约束：通过项必须可复核，数字必须来自当次运行。

## 未做项清单（Not-done list）

[[cloud-world 桌面端]] 2026-11-12 验收原样保留的 4 条：

| # | 未做项 | 隐含风险 |
| --- | --- | --- |
| 1 | 只跑 `--no-bundle --debug`，未产出 NSIS 安装包；nsis 目标与图标未走正式打包流程 | 部署模型未验证 |
| 2 | 只在 Windows 实测；`DETACHED_PROCESS` 是 Windows API，macOS/Linux 等价路径未验证 | 跨平台可行性未知 |
| 3 | 界面不提供 `--config-dir` / `--claude-dir` 入口，隔离测试靠环境变量 | 用户无法自助切换目录 |
| 4 | `clippy` 不可用（`cargo-clippy.exe` 缺失），只做 `cargo build` + `cargo test` | 无 lint 结论，不等于代码质量已检查 |

## 证据类型（本次实践）

- 构建与测试：`cargo build` 无警告、`cargo test --workspace` 73 passed / 0 failed。
- 前端产物：`tsc --noEmit` + `vite build` 通过。
- 端到端连通性：[[真实请求链路]] 返回 HTTP 200 / 1685 ms / `"pong"`。
- 诊断分级（`ok / warn / fail`）：隔离 profile `13/5/0`，生产 `16/2/0`；隔离环境的 WARN 全为「未连接 + dev_resolve」这类预期项。
- 数据一致性：85 条资产可见，默认资产与 CLI 一致。
