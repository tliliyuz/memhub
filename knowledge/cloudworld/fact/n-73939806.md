> 用 --target-dir target-build 绕开被 watchdog 锁定的 target\debug\，代价是产物路径非正式、需人工记忆、.gitignore 必须补 target-build/。

# 定义

构建目录隔离指把本地构建输出从默认 `target\` 改到独立目录：

```powershell
cargo build --target-dir target-build
```

产出位于 `target-build\debug\`，与生产实例使用的 `target\debug\cloud-world.exe` 完全分开。

# 背景（为什么需要）

[[watchdog 计划任务]] 长期维持生产 [[relay 后台进程]]，其 `$relayExe` 指向 `target\debug\cloud-world.exe`，该文件被文件锁占用。直接 `cargo build` 会因文件锁失败，或替换掉正在运行的生产二进制。

# 取舍

| 项 | 说明 |
| --- | --- |
| 好处 | 不碰被占用的 `target\debug\`，生产 relay 不受影响 |
| 代价 | 产物在 `target-build\debug\`，**不是正式产物位置**，需人工记住路径 |
| 附带要求 | `.gitignore` 必须包含 `target-build/`，否则隔离目录反而污染仓库 |

# Significance

- 让「本地调试构建」与「生产运行实例」在同一台机器上共存，是开发与运维共机的必要约束。
- 与 [[relay 单实例与端口互斥]] 同属「开发态与生产态共存」的一组约束。
