> 同一「无效 key」在 verify 端点是成功校验（valid=false），在 meta action 是 401 错误；分支必须以 valid 布尔值判定。

# Definition

[[memhub 云端面板 API]] 中，同一个「无效 [[user_key]]」在不同端点上呈现出**不同语义**：

| 端点 | 无效 key 表现 | 语义 |
| --- | --- | --- |
| [[meta-auth-verify 端点]] | HTTP 200 + `code=0` + `valid=false` | **成功的校验结果为否**（不是错误） |
| [[meta-action 端点族]] | HTTP 401 + `code=401` | **错误**（鉴权失败） |

# Significance

- **错误分支必须以 `valid` 布尔值判定**，而不是 HTTP 状态码。按状态码统一判鉴权会让 verify 路径永远走「成功」分支，从而把「无效」误当「有效」。
- 这是 [[响应形状三分法]] 的语义侧延伸：形状不同 → 载荷位置不同 → 判定依据不同。
- 与 [[错误码判定表]] 联动：`401 code=401` 只属于 meta action 族，不可外推到 verify。
- 对封装的启示：[[cloud-api-crate]] 中 `verify_user_key` 与 `list_accessible_assets` 必须返回语义不同的结果类型（校验结论 vs 错误），不能合并成同一个 Result 语义。
