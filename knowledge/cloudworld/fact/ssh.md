> 用 loopback SSH 隧道绕开 SNI 层拦截的过渡技术方案，依赖本机隧道与 watchdog 存活，属规避而非修复。

# 定义

SSH 隧道过渡方案：在 [[备案拦截（ICP 备案未完成阻断）]] 无法短期消除的前提下，通过本机 SSH 隧道把 `127.0.0.1:8443` 映射到 `服务器:443`，客户端改为访问 loopback 地址，从而在握手阶段不暴露被拦截的域名。

**这是过渡方案不是修复**：它让服务在受限网络下可用，但不改变根因，也不改变公网对该域名的拦截状态。

# 机制

| 环节 | 内容 |
| --- | --- |
| 隧道映射 | `127.0.0.1:8443 → 服务器:443` |
| 客户端改动 | 访问 `127.0.0.1:8443`（loopback），不再直连域名 |
| 绕开点 | 握手阶段不发送被拦截的 SNI（[[SNI 分叉判据]] 中「不带 SNI 活」的那条通路） |
| 服务端 | 仍由 [[Nginx]] 终结 TLS，证书与配置不变 |

# 依赖组件：tunnel watchdog

隧道存活状态决定方案是否生效，需要 watchdog 维持。当前以 `scripts/memhub-tunnel-watchdog.ps1` 实现，负责存活检测与重启；其头部注释记录了该方案的存在理由：

> 域名备案未完成，公网 HTTPS 被阻断，必须走 SSH 隧道过渡

运维语义：隧道是客户端本机进程，进程退出、网络切换、机器休眠都会使服务不可用，因此「服务可用」这一结论**在本机隧道存活期间才成立**。

# 代价与限制

- **依赖本机**：只在装了隧道与 watchdog 的机器上可用，不是对全部访问者的通用解法。
- **不是修复**：公网访问者仍受拦截影响，根因未消除。
- **可观测性变差**：故障可能来自隧道、watchdog 或服务端，排障需先确认隧道状态。
- **不可与代理方案混为一谈**：改代理 `DOMAIN-SUFFIX` 走境外节点只是概率性避开某些出口，`res` 多地区 reset 表明不是所有出口都通。

# 退出条件

当下列任一条件满足时应撤销本方案，改为常规公网访问：

- [[memhub.work]] 完成 ICP 备案；
- 换用已备案域名承载服务。

即长期只有这两条根治路径。
