> 账号默认 > 请求头预设 > 交互表单的短路式三级解析，命中前一档即完全跳过后续档（含请求头）。

# 定义

资产解析优先级链是服务端在新建会话时确定 team / agent / task 的三级短路解析规则：

```
账号默认（user-session-default） > 请求头预设 > 交互表单
```

命中前一档即**完全跳过**后续档位，不存在「合并」或「覆盖部分字段」的语义。

# 三级档位

| 档位 | 载体 | 生效条件 | 被跳过的内容 |
| --- | --- | --- | --- |
| 第一档 | [[账号级默认会话资产记录]] | 账号存在 `user-session-default` | [[请求头预设]] + [[交互式资产选择表单]] |
| 第二档 | [[请求头预设]] | 无账号默认，且请求头有指定 | [[交互式资产选择表单]] |
| 第三档 | [[交互式资产选择表单]] | 前两档均未命中，且为交互会话 | — |

# 重要性

- 决定「新会话不弹资产选择表单」「`x-agent-id` 指定无效」等现象的归因，避免误判为故障或配置泄漏。
- 决定了运维动作：要改变取值只能删除第一档载体，而不能通过请求头覆盖。
- 是 [[预期行为 vs bug 判定]] 的核心依据。

# 开关边界

该链**没有分档开关**。唯一的开关是 [[会话初始化]] 的 `sessionInit.enabled`（默认 `false`），关掉等于整条初始化链路停摆，而不是「跳过第一档」。因此「找不到只关这一档的开关」是符合设计的。
