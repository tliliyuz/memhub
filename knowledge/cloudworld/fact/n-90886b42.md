> 因 claude -p 无法渲染确认表单，将 team/agent/task 固化到账号级是非交互会话获得确定取值的唯一办法，代价是交互会话也不再询问。

# 定义

非交互会话资产固化指把 team / agent / task 的选择持久化到**账号级**（即 [[账号级默认会话资产记录]]），使非交互模式（`claude -p`）下的会话也能获得确定的团队与执行主体。

# 重要性

- `claude -p` 等非交互会话**无法渲染**确认表单，因此 [[交互式资产选择表单]] 这一档对它们不可用。
- 在没有账号默认的情况下，非交互会话除请求头外没有取值来源；固化到账号级是其获得确定 team/agent/task 的**唯一办法**。
- 这也解释了 [[资产解析优先级链]] 为何把账号默认排在最高档并采取短路语义——固化值必须足够「硬」，才能保证非交互会话的确定性。

# 代价与取舍

| 收益 | 代价 |
| --- | --- |
| 非交互会话获得确定的 team/agent/task | 同一账号下的交互会话也不再询问用户 |
| 解析结果稳定、可预测 | 请求头指定被静默忽略，容易误判为 bug |

# 相关实体 / 概念

- [[交互式资产选择表单]]：非交互模式下无法渲染，是本设计存在的动因。
- [[账号级默认会话资产记录]]：固化的载体。
- [[资产解析优先级链]]：固化值所处的最高档位。
- [[预期行为 vs bug 判定]]：用于把上述代价归类为预期行为。
