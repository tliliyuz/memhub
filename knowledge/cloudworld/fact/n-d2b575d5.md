> UNKNOWN_META_ACTION、MISSING_TEAM_ID、limit 上限、401 各有独立含义，不可互相误判。

# Definition

[[memhub 云端面板 API]]（尤其 [[meta-action 端点族]]）的失败返回按语义分类如下，**不可互相误判**：

| 返回 | 含义 | 不要误判为 |
| --- | --- | --- |
| `404 UNKNOWN_META_ACTION` | action 名不存在（路径/动作名写错） | 无权限 / 服务未部署 |
| `400 MISSING_TEAM_ID` | 缺 [[team_id]] | 身份无效 |
| `400 limit: Too big: expected number to be <=100` | 分页上限 100 被突破 | 服务端 bug |
| `401 code=401` | [[user_key]] 无效 | 网络问题 |

补充一条同属「参数缺失」类的实测返回：body 中没有身份字段时返回
`400 {"code":400,"message":"(root): user_id or user_key is required"}`（见 [[身份参数载体约束]]）。

# Significance

- **排障顺序**：先确认 action 名（404）→ 再确认租户维度（400）→ 再确认分页参数（400）→ 最后才怀疑凭据（401）。把「路径不对」当「没权限」会浪费大量排查时间。
- **鉴权判定的边界**：`401` 只在 meta action 族代表 key 无效；[[meta-auth-verify 端点]] 的无效 key 走 `200 + valid=false`，见 [[无效凭据语义分裂]]。
- **客户端映射**：[[cloud-api-crate]] 的 `list_accessible_assets` 侧做了 `limit` 校验，可以在请求前拦截而不必等服务端报错。
