> 一个合格的工程名必须能派生出仓库、crate、二进制、配置目录、凭据条目等全部标识，且各层形式一致。

# 定义

标识同构派生（命名一致性）指：选定工程名后，所有工程层级的标识都必须由它按统一规则机械派生，不允许某一层另起名字。

[[cloud-world]] 的落地清单（出自 [[07-命名决策]]）：

| 层 | 派生形式 | 实例 |
| --- | --- | --- |
| 仓库 | 产品名 | `cloud-world`（对外 `<org>/cloud-world`） |
| crate | `产品名-职责` | `cloud-world-core` / `-api` / `-relay` / `-service` / `-cli` / `-desktop` |
| 二进制 | `产品名` 或 `产品名-端类型` | `cloud-world`（CLI）、`cloud-world-desktop` |
| 配置目录 | `产品名` | `%APPDATA%\cloud-world` |
| 凭据条目 | `产品名 / <profile>:<凭据名>` | `cloud-world / <profile>:panel-user-key` |

# 意义

- 让 CLI 高频输入的名字短、可预测、不易拼错（大小写与连字符规则固定）。
- 新增服务或新端时无需再开命名讨论，直接套用派生规则。
- 是 [[产品命名判据]] 第二维度的具体标准；不满足该标准即触发 [[命名漂移与迁移成本]]。

# 各层注释

- **crate 层**：发布前需在 `crates.io` 上验证占用，搜索无同名**不等于**未占用，必须 `cargo publish --dry-run`。
- **配置目录层**：平台相关路径（Windows 为 `%APPDATA%`），目录名不含组织前缀，因此与仓库名不同构 —— 这是有意的，重名风险只存在于公共托管命名空间。
- **凭据条目层**：包含 `<profile>` 占位，未来若引入权限 / 凭据模型，该片段应升级为独立概念页。

# 反例

`Nature-reawakens` 在每一层都会派生成长串，且 GitHub 强制小写连字符为 `nature-reawakens`，显示形式与书写形式不一致 —— 违反同构性。详见 [[07-命名决策]] 的"被否决的方案"小节与 [[工程名与代号分离]]。
