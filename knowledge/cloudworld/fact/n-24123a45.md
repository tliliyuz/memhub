> 凭据是功能硬门槛而非界面门槛——缺 key 时连接被拒绝且不写任何文件，边界由「能否建立连接」划定。

# 凭据边界

## Definition

凭据边界是指：系统的安全边界由**能否建立连接**划定，而不是由**能否进入界面**划定。`user_key` 缺失时，连接请求被拒绝，且**不产生任何文件**；凭据只存在于 [[系统凭据库]]，绝不进入 [[配置文件 config.toml]] 或命令行。

## Significance

- 明确「功能硬门槛」与「界面门槛」的分工，避免把安全检查寄托在 UI 流程上（见 [[界面门槛与鉴权分离]]）。
- 以「不写任何文件」作为失败时的强约束：失败路径不留下可被搜集的痕迹。
- 负向定义同样重要：配置文件「不含任何密钥」正是边界的另一半。

## Related Entities

- [[系统凭据库]] — 边界内唯一允许持久化密钥的位置。
- [[凭据模块]] — 边界的读写闸门。
- [[配置文件 config.toml]] — 边界的负向基线（明文、无密钥）。
- [[桌面登录门禁]] — 界面侧的表现，但不是边界本身。

## Common Topics

- **权限模型**：密钥的存放与读取权限集中在凭据库。
- **数据流**：边界延伸到传输层，见 [[key 生命周期数据流]]（请求时把 key 放进 JSON body 而非 header）。
- **安全机制**：见 [[密钥不落盘原则]]、[[多 profile 隔离]]。

## Schema

| 情形 | 结果 |
| --- | --- |
| 凭据库有对应 key | 允许发起连接 |
| 凭据库缺 key | 连接被拒绝，且不写任何文件 |
| 界面已进主视图 | 不代表已通过鉴权 |
