> 用 --data-binary @file 或 curl -K 配置文件传递 key，用完即删，避免命令行与进程列表泄露。

# Definition

在命令行环境调用 [[memhub 云端面板 API]] 时安全传递 [[user_key]] 的操作约定：

- **不要把 key 放进命令行参数**——argv 对同机其他用户可见（`ps`、`/proc/*/cmdline`）。
- 写临时文件，用 `curl --data-binary @file` 传 body。
- 或写 curl 配置文件，用 `curl -K config` 传入。
- **用完即删**临时文件，避免长期落盘。

# Significance

- 与 [[身份参数载体约束]] 互为表里：API 要求身份进 body（不放 header），而 body 需要以安全方式构造，才不把风险从 header 转移到命令行。
- 该实践同时降低误触发副作用的概率：探测 key 用 [[meta-auth-verify 端点]]（只读），绝不用 [[auth-user-key-login 端点]]（会自动注册，见 [[自动注册语义]]）。

# Examples

```bash
# 方式一：body 来自文件
printf '{"user_key":"%s"}' "$KEY" > /tmp/body.json
curl --data-binary @/tmp/body.json -X POST https://<host>/api/v1/meta/auth/verify
rm -f /tmp/body.json

# 方式二：curl 配置文件（-K）
# verify.conf:
#   url = "https://<host>/api/v1/meta/auth/verify"
#   data = "{\"user_key\":\"...\"}"
curl -K verify.conf && rm -f verify.conf
```
