# 密钥不落盘原则

## Definition

密钥不落盘原则规定了 `user_key` 全生命周期中允许出现的介质：不上日志、不进命令行、不进仓库、不进普通配置文件；内存中不复制、用后清零；必须落地的临时文件用完即删。

## Significance

- **命令行不可用**：Windows 上进程命令行对其他用户可见（`Get-CimInstance Win32_Process`），`--key xxx` 等于把密钥写进系统日志。
- **配置文件不可用**：[[配置文件 config.toml]] 是明文，容易进备份、进 git、进截图。
- 因此唯一被允许的持久化位置是 [[系统凭据库]]（见 [[凭据边界]]）。

## Related Entities

- [[凭据模块]] — 输入侧落点：隐藏输入或 `--stdin`，**拒绝命令行位置参数**，输出不回显。
- [[桌面登录入参]] — 内存侧落点：刻意不实现 `Debug` / `Clone`，key 只搬进一个缓冲区，用后 `zeroize()` 原地清零。

## Common Topics

- **内存安全**：不实现 `Debug`（防 `{:?}` 落日志）、不实现 `Clone`（防多份拷贝）、`zeroize()`。
- **传输与临时文件**：写临时文件时用 `--data-binary @file` 或 curl `-K` 配置，用完即删（见 [[key 生命周期数据流]]）。
- **供应链/仓库卫生**：密钥不进仓库。

## Schema

| 介质 | 是否允许 | 原因 |
| --- | --- | --- |
| 系统凭据库 | ✅ | 加密存储 |
| 命令行参数 | ❌ | 进程命令行对其他用户可见 |
| 日志 / `Debug` 输出 | ❌ | 可被搜集 |
| 普通配置文件 / 仓库 | ❌ | 明文、易扩散 |
| 进程内存缓冲 | ⚠️ 短暂 | 单一缓冲，用后 `zeroize()` |
| 临时文件 | ⚠️ 短暂 | `--data-binary @file` / `-K`，用完即删 |
