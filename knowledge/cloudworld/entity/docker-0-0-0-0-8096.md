> 与本系统无关的第三方本地 docker 栈，其对 8096 的绑定方式（非独占通配 / 独占 / loopback）决定 cloud-world relay 能否启动。

# 定义

本机上与本系统**无关**的另一套 docker 服务栈，常已监听 `0.0.0.0:8096`。它是 relay 端口冲突的主要外部来源，但双方不存在任何调用或依赖关系。

# Key Attributes

- 典型绑定形态：`0.0.0.0:8096`（通配地址）。
- 绑定是否独占（是否启用 `SO_EXCLUSIVEADDRUSE`）决定冲突结果：非独占时 [[cloud-world relay]] 的 `127.0.0.1:8096` 仍可并存；独占时 relay 绑定失败（`os error 10013`）。
- 若其改为占用 `127.0.0.1:8096`，relay 同样绑定失败。
- 行为在 Windows 上依实现/机器而异，**不能凭一次现象推广**。

# Relationships

- [[cloud-world relay]]：不同程序，仅在 8096 端口上争用；冲突形态见 [[端口绑定共存模型]]。
- 处置手段（改端口 / 停对方 / 改变独占性）见 [[端口占用排查流程]]。
