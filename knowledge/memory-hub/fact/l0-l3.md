# 记忆分层 L0–L3

## 定义

[[Chat Memory]] 的内部结构按粒度分为四层，逐层下沉、体量递增：

| 层 | 内容 | 用途 / 典型用途 |
|---|---|---|
| L3 | 长期画像 / 稳定偏好 | 常驻上下文，默认注入；快速建立对项目/人的整体认知 |
| L2 | 场景索引（摘要 + 指针） | 决定「要不要展开」；定位「哪次讨论涉及什么」 |
| L1 | 原子记忆（单条事实/决策） | 精确定位；单条事实、决策、术语 |
| L0 | 原始会话 | 溯源与原文核对；需要原文时的最终依据 |

Agent 按需查询下钻，而非全量注入；具体可从 L3/L2 索引下钻到 L2 正文与 L0 原文。

## 意义

- 控制上下文成本与信噪比：先看 L3/L2，需要时再取 L0 正文；分层让读取成本可控，先看索引，再决定是否取原文。
- L0/L1 的 `total` 增长可作为记忆生效的验证判据（区别于「回复正常但不记记忆」的静默失效）。

## 对外读取接口（2026-11-10 起）

- 会话内：[[Memory Proxy]] 暴露 L3 / L2 索引。
- 离线 / agent 通用：[[Team Brain MCP]] 的 **`chat_memory_layer`** 是该分层的对外读取接口，可指定层与数量；它是 Team Brain MCP 的 5 个 `chat_memory_*` 工具之一。后端为 [[Memory Hub]] 8125 的 `/api/v1`，需要 `sk-mem-` 用户密钥，见 [[MCP 双后端只读接入]]。
- 约束：`chat-memory/layer` 的 `limit` **上限 100**，传 200 会 `400`（MCP 层已 clamp，调用方不必自己截断）；配套 `chat_memory_agents` 用于取得合法 `block_id`（`chat_memory-<team_id>-<agent_id>`）。
- 同批工具还包括 `chat_memory_agents`（列 agent / 拿 `block_id`）、`chat_memory_search`、`chat_memory_list`、`chat_memory_stats`。
