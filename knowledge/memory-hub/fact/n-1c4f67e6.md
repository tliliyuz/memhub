> .env 缺少 PROXY_ENABLE_* 时启动脚本会生成全关闭配置，必须显式写入四项开关并校验生成的 config.yaml 才不丢记忆。

# 定义

[[Memory Proxy]] 的能力（记忆注入、鉴权、会话初始化、知识检索）由生成出的 `config.yaml` 中的 `enabled` 开关控制。这些开关**不由默认值兜底**：`.env` 里缺少 `PROXY_ENABLE_*` 时，[[start-proxy 启动脚本]] 会生成一份**全关闭**的配置，记忆注入直接失效。

「显式固化」即把这四项在 `.env` 中写死：

```env
PROXY_FULL_STACK=1
PROXY_ENABLE_AUTH=1
PROXY_ENABLE_TDAI=1
PROXY_ENABLE_SESSION_INIT=1
```

# 显著性

生成结果必须是：

| config.yaml 字段 | 期望值 | 关闭后的后果 |
|---|---|---|
| `tdai.enabled` | `true` | 不记 L0/不注入记忆 |
| `auth.enabled` | `true` | 鉴权链路失效 |
| `sessionInit.enabled` | `true` | 会话初始化缺失，记忆绑定不成立 |
| `knowledge.enabled` | `true` | 知识检索（[[Wiki]] 链路）不可用 |

**任一为 `false`，记忆链路就是断的。** 恶劣之处在于：服务完全正常、模型正常回复，只是不记记忆——从外部完全看不出来，属于典型的 [[静默失效与健康检查盲区]]。

# 校验方法

```powershell
docker exec tdai-proxy head -12 /data/config.yaml   # 检查四项 enabled: true
```

改 `.env` 后必须重跑 [[start-proxy 启动脚本]]（Proxy 不认环境变量），否则开关不生效。

# 与其他概念的关系

- 成因归属：本概念是 [[静默失效与健康检查盲区]] 两大故障模式之一的具体成因。
- 若开关正常但记忆仍不涨，转到 [[级联代理拓扑与分层顺序]] 的五步验证继续排查。
