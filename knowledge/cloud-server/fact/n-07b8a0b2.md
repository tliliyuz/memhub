> memhub 记忆栈的两条反向调用链：Agent→proxy→gateway→上游（注入），浏览器→nginx→panel→knowledge/core（浏览）。

# 记忆栈服务拓扑

## 定义

memhub 记忆栈由三层构成：公网接入层（[[nginx]]）、记忆服务层（[[tdai-memory-hub]]、[[tdai-memory-core]]、[[tdai-proxy]]）、模型路由层（[[magpie gateway]]）。所有进程运行在单台 [[腾讯云 CVM VM-0-10-ubuntu]] 上。

## 两条调用链

```
Claude Code / Agent
  → 127.0.0.1:8096  (tdai-proxy，记忆注入)
  → 172.17.0.1:3425 (magpie gateway，模型路由)
  → 上游供应商

浏览器
  → https://memhub.work (nginx:443)
  → 127.0.0.1:8125  (tdai-memory-hub 面板)
      ├─ 127.0.0.1:8424 (knowledge)
      └─ 127.0.0.1:8420 (tdai-memory-core)
```

两条链方向相反：**注入链出站**（读/写记忆 + 调模型），**浏览链入站**（人看面板）。它们共享 [[tdai-memory-hub]] / [[tdai-memory-core]] 与同一份数据卷。

## 意义

- 明确了"谁能访问谁"的可达性矩阵，是 [[最小暴露面绑定原则]] 的推导依据。
- 明确了单点：任一组件（尤其 [[tdai-memory-core]]）故障或 OOM 都会中断两条链路 → [[资源配额与 OOM 风险]]。
- 部署顺序由 [[memhub-stack 服务单元]] 固化为 `core → hub → proxy`。
