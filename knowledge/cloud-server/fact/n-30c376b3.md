> 云主机并非完全自主——云厂商的 agent（如百度智能云 bcm-agent / checkmce / bsm-agent / has-agent）需常驻且不可重启或改动，构成运维操作的硬边界。

# 定义

云厂商托管组件约束指：云服务器上除业务进程外，还存在由云厂商注入并维护的 agent 进程，
它们**不在运维者的变更权限内**（不得重启、停止、修改配置），因而成为排障与加固时的
不可触碰区域。

# Schema

| 维度 | 约束内容 |
|---|---|
| 生命周期 | 由云侧控制，禁止本侧 stop / restart / disable |
| 配置 | 禁止修改，端口与行为视为黑盒 |
| 端口 | 可能直接监听 `0.0.0.0` 并对公网可达（A 机：781、428） |
| 责任边界 | 出现异常应上报云厂商，而非本侧修复 |

# Examples

[[服务器 A（instance-47g8z54m）]] 上的实例：`bcm-agent`（781）、`checkmce`（428）、
`bsm-agent`、`has-agent`，见 [[百度智能云主机安全与管理组件]]。原文运维注意事项第 1 条即为
「**不要重启、停止或改动**」。

对照：[[腾讯云 CVM VM-0-10-ubuntu]] 一侧的云侧防线以 [[腾讯云安全组]]（YJ-FIREWALL-INPUT）
形式存在，属**主机外**的网络层，不占用主机内进程；A 机的云侧边界则同时体现为
主机内 agent + 未核实的安全组。

# 意义

1. 审计盲区：这些端口是公网可达的，但不在本知识库的可解释范围内——做暴露面评估时必须显式标注。
2. 变更风险：批量加固脚本（如统一停用非必要服务）会误伤云厂商 agent，导致主机失联。
3. 资源竞争：A 机仅 1886 MiB 内存，agent 与 [[ClickHouse]] 共享同一内存池，
   进一步压缩可用余量（见 [[资源配额与 OOM 风险]]）。
