> 主机防护的互补分层模型：B 机为安全组→fail2ban→SSH 认证→nginx 限流四层，A 机为云厂商边界/agent→fail2ban→SSH 密钥-only + 双端口三层；另含结构性绑定层。

# 主机安全防护分层

## 定义

主机安全防护分层指用多个**互补而非重复**的层次堆叠出入侵成本：网络边界过滤、动态封禁、认证策略收紧、应用层限流。旧页给出的“安全组（边界）→ fail2ban（动态封禁）→ SSH 认证策略 → nginx 限流与安全头”是 B 机的四层形态；新页补充 A 机为三层变体（无 L4）。两者按主机角色不同而不同，不矛盾。

在 B 机上，主机安全不是单点配置，而是四层叠加；A 机则裁剪掉应用层，并加强了认证层。

## Schema

| 层 | 组件 | 职责 | B 机（[[腾讯云 CVM VM-0-10-ubuntu]]）现状 | A 机（[[服务器 A（instance-47g8z54m）]]）现状 |
|---|---|---|---|---|
| L1 / 旧 0 边界 | B：[[腾讯云安全组]]（`YJ-FIREWALL-INPUT`）；A：[[百度智能云]] 侧边界 + [[百度智能云主机安全与管理组件]] | 云侧入站过滤 | 生效；ufw 未启用，iptables 默认 ACCEPT | 百度智能云侧边界 + 主机内 agent 监听 `0.0.0.0` 的 781 / 428（**规则未核实**）；ufw 未启用，iptables 默认 ACCEPT |
| L2 / 旧 1 动态封禁 | [[fail2ban]] | SSH 暴力破解后按 IP 封禁 | 生效（1.0.2）：`findtime=10m, maxretry=5, bantime=1h`，递增 ×2 上限 1 周，白名单 `127.0.0.1`、`180.173.121.131` | 已生效，`f2b-sshd` 链，封禁 5 个 IP |
| L3 / 旧 2 认证策略 | SSH | 降低猜测成功率 | `PermitRootLogin without-password`、`MaxAuthTries 6`；root 密码禁用，但 `PasswordAuthentication yes` **仍开启** | `PermitRootLogin without-password` + `PasswordAuthentication no` + `MaxAuthTries 6`；SSH **22 与 2222 双端口** |
| L4 / 旧 3 应用层 | [[nginx]] | 限流 + 安全头 | `/api/v1/auth/` 6 次/分（burst 4），其余 30 次/秒（burst 60）；nosniff / SAMEORIGIN / no-referrer / 隐藏版本号 | **无**（A 机无 Web 入口） |

A 机只有三层，因为无公网 Web 负载，L4 缺失；其补偿是“零 Web 暴露面”本身。

## 绑定层（结构性保障）

绑定层不属于“防护”而属于“不可达”，是上述各层之外的结构性保障：B 机遵循 [[最小暴露面绑定原则]]；A 机的 [[ClickHouse]] 全端口回环绑定（[[回环绑定与 SSH 隧道访问]]）使 L1 被误配置时数据库仍不可达。

## 关键差异

1. **A 机只有三层**，因为无公网 Web 负载，L4 缺失；其补偿是“零 Web 暴露面”本身。
2. **A 机认证更严**：密码认证已关闭、root 仅密钥；B 机密码登录仍开启，属待收紧项。
3. **A 机多一个攻击面**：SSH 双端口（22 + 2222）意味着两条爆破入口，需确认 [[fail2ban]] jail 对两者都生效。
4. **A 机 L1 是黑盒**：云厂商 agent 直接监听 `0.0.0.0` 上的 781 / 428，本地无法审计其规则（[[云厂商托管组件约束]]）。
5. **ufw 在 A 机未启用**，iptables 默认 ACCEPT；换言之 A 机的入站过滤实质依赖云侧策略 + fail2ban，与 B 机“ufw 未启用但安全组确定生效”的处境相似。

## 意义

- 分层使单层失效不致命：即使安全组规则疏漏，fail2ban 仍遏制爆破；即使密码认证开着，root 密码登录已被禁。
- 明确指出**缺口与优先级**：B 机密码认证仍开启（应关闭）、ufw 未启用（可选增强，与安全组职责重叠）；A 机需核实云侧安全组规则与 SSH 双端口的 fail2ban 覆盖情况。
- 实测数据支撑判断：近 7 天 SSH 失败 11 次（主要来源 `77.239.124.46`，8 次，已被安全组 REJECT），唯一成功登录为 [[管理员账号]]（`180.173.121.131`）。
- 说明“分层”不是照抄模板，而是按主机角色裁剪：A 机裁剪掉 L4、加强了 L3；B 机保留四层但 L3 待补。
- 后续加固优先级：B 机关闭密码登录；A 机核实云侧安全组规则与 SSH 双端口的 fail2ban 覆盖情况、评估是否关闭 2222。
